## 实现

### 每槽位的可追溯诊断

`writer_diagnostic.slot_lines['<item_id>:<slot>']`（包括 `positioning`）记录：

- `selected_fact_ids`：入选事实；`writer_output`：正文 writer 原始行，早于指标补回、清洗和 polish。
- `attempts`：model / retry / deterministic_fallback，每次保存文本、fact_ids、原始模型行、verdict、failures；子句校验保存词法错误与语义完整维度，反向覆盖保存逐 fact_id 的结果。
- `failures[].category` 分为数字、实体、动作、状态、否定、限定、语义覆盖、其他；保留具体错误码、失败子句/事实和 unsupported_spans。
- `retry_count`、`final_handling`、最终文本/引用；结构不合格、跨槽引用、错 repair ID、模型不可用、显式条数上限或全约束事实均可见。最初校验始终使用原始 writer 行，旧 polish/coverage 补回不能掩盖原始错误。

### 概括通过子句与事实集合核验

原 forward guard 已支持合并引用，不是“整行必须等价于单条事实”；问题是整行检查/反向检查一票否决及兜底再次依赖模型。本批在 labeled 最后一道门按逗号、分号、句号拆子句，各子句可以由不同事实支持，并附整行供主语/指代解释。每个引用事实另核对核心语义覆盖，不能靠多挂 ID 掩盖缺失指标。

只对 labeled 问题槽应用明确白名单：`一个一个/逐个/逐一/逐项`、`繁杂/低效/繁琐`、`复制粘体/复制粘贴`。使用整子句相等做确定性快速匹配，不做模糊相似度放行；其它概括仍由语义核验。删除“甚至/非常”只允许减少口语程度，不能新增显著/严重、频率、因果、数字、实体、动作或状态。数字单位、约/仅/本地/虚拟、或/和的区别继续保留。普通无标签路径不使用该白名单。

给定合并例句“普通简历工具需逐项填空，AI 优化的经历要手动复制粘贴；生成的 PDF 无法编辑，且不懂简历结构”通过逐子句语义桩；`一个一个→逐项`、`繁琐→低效`的整子句等价不依赖语义服务即可通过。未实测真实模型对自由概括的稳定性。

### 一次修复，之后一定保留可写事实

正文缺失/失败槽一次 `writer_slot_repair`，把上次文本和具体失败项交给模型。再次失败后，直接规范化该槽 active fact.text、去重、分号拼接并带标签、有效 fact_ids 和 coverage_fact_ids。**兜底不再次调用语义模型，也不使用模型失败文本。** 长公共子串、超过模型 240 字/3 句的事实兜底允许保留；条目总行数上限、backup 和用户明确零行等选择仍生效。

口语“甚至/非常/差点意思”清洗；真实现状保留“效果仍在优化”。“可能上线”变为“是否上线尚待确认”，不能删除不确定性后冒充已上线。限定、数字单位及原始事实母版均不改。纯约束/缺失数据不输出；混合槽只引用实际输出的事实。从 c5 现稿续写时，正文成功恢复后清除本条目旧的交付失败提示，保留其它核对事项。痛点中的“无法编辑/不懂结构”是产品问题，不作为纯否定约束吞掉。

项目 positioning 同样一次带失败项修复，之后只从本项目的用户/学生、简历工具/助手等已知问题、功能或现状概括“面向 X 的 Y”；目标人群或类别不足才留空，不从岗位目标造身份或功能。当前两人物兜底分别为“面向用户的简历工具”“面向学生的AI简历助手”。

技术槽只收工具、框架、模型、API；产品功能进入标题性质供 positioning 使用，提示词/原型的本人分工不冒充技术栈。未扩展抽取范围，也未改真实回放输入。

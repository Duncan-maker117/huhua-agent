# 后端开发（校招 / 实习，Java / Go / Python / C++）

## 筛选者看什么（按权重）
1. **技术栈与 JD 对得上**：语言、框架、数据库、中间件（Spring Boot、MySQL、Redis、MQ、Docker）。每个写在技能区的技术，最好在经历里有一处真实使用。
2. **自己实现了什么**：负责的模块/接口/服务，而不是项目整体介绍。证据：具体模块名、接口数、表设计、核心逻辑。
3. **技术难点与方案**：并发、缓存、一致性、性能、幂等、限流、分库分表等，**遇到了什么问题、怎么解决**。这是区分"做过 CRUD"和"有工程能力"的关键。
4. **量化的工程结果**：QPS、响应时间、吞吐、错误率、资源占用、数据量。
5. **工程素养**：测试、CI/CD、监控、日志、代码规范、Code Review、上线部署。
6. 基础：计算机基础、算法竞赛（ACM/蓝桥杯/LeetCode 量）、开源贡献。

## 学生能拿出的证据
课设/毕设、实验室项目、实习、开源 PR、个人项目（部署在服务器上的）、竞赛。

## 成果口径
- 性能：接口响应时间 X ms → Y ms、QPS、压测数据（注意说明是否压测环境）
- 规模：数据量（行数/日志量）、用户/请求量、服务数、接口数
- 稳定性：错误率、可用性、故障数
- 效率：部署时间、开发效率、代码复用
- 状态：本地 Demo / 部署在服务器 / 生产环境

## 表达
- 推荐动词：设计、实现、开发、重构、优化、引入、定位、排查、部署
- 句式：**[针对什么问题/场景]，[用什么技术方案]，[实现/优化了什么，结果]**
- 例："基于 Redis 分布式锁 + 库存预扣减实现秒杀下单，避免超卖"
- 避免："熟悉 Java 开发""参与项目的后端开发工作"这种无模块无方案的句子。

## 改写示例（方法演示）
- 原话：「课设做了个图书管理系统，springboot 加 mysql，我写的借书还书那块，还加了 redis 缓存热门书」
- 改写：「开发借还书模块（Spring Boot + MySQL），对热门图书查询引入 Redis 缓存」
- 说明："我写的那块"支持"开发"；是否整个模块都由本人负责，需追问后才写"负责"。
- 追问："加缓存之前和之后，查询大概多快？缓存和数据库不一致你怎么处理的？"

## 高价值追问
- "你自己写的是哪几个模块/接口？"
- "做的过程中最难的一个技术问题是什么？怎么解决的？"
- "有没有测过性能？优化前后差多少？"
- "部署在哪里？现在能访问吗？有没有真实用户？"

## 常见坑
- 技能区列了 K8s/微服务/Kafka，经历里一处都没有。
- 把框架自带能力写成自研（"实现了 ORM 映射"）。
- 压测数据不说环境，或把本地测试写成线上指标。

# raw_notes 限制补全的有界安全评估

结论：**在仅修改 fact_extractor + 新测试、不得处理历史回放/编辑指令/多归属/更正删除的约束下，不实施自动 raw_notes → status_limit 补丁。** 这是实现前安全评估，不是认为“限制遗漏可接受”。未修改 MAIN、候选源码或旧 run；未调用模型、未运行业务测试。只用 AST 提取现有纯函数核对文本过滤边界。

## 现有接口不足以证明两项前提

1. `fact_extractor.py:90–91` 接收普通字符串，`turn_id` 默认空；`resume_graph.py:890–900` 的生产调用不传轮次或来源类型。
2. `resume_graph.py:739–752` 将多个历史 HumanMessage 用两个换行拼成 `source`，再走相同提取接口。此层无法区分“本轮新声明”与“旧声明重放”。检查换行不能解决单条历史回放，也不能把所有多段真实材料一概证明为历史。
3. `fact_extractor.py:147–166` 的 raw_notes 只做消息子串检查；既有 item_id 只验证该 ID 存在。条目归属仍由模型给出，raw_note 不是经过独立归属核验的事实。一个 patch 只含一个 item，不证明消息只谈了一个经历。
4. 现有 active source_quote 是局部被验证的文本。补齐另一个子句后，其主体、时态、资料类型可能变化；_limit_clauses 只识别限制文本边界，不判别资料归属或当前有效性。

## 对两个 v4 用例的实际影响

- career-switch turn4 的原句为“我保留了分类前后的例子和自己的检查备注，但没有正式评测集或准确率统计。”，确实应保留全部限制。不过当前 collected 同时有社团运营与活动问答整理，句中没有项目名；若只因模型把完整 note 放在后者就自动补全，相当于新增了一条归属信任规则。可以考虑未来只补一个**已接受 status_limit 来源所在同一连续子句**的遗漏并列宾语，但这仍不能证明输入是当前轮、更正是否失效；且不覆盖 pm 只有 note 的情况。
- pm 原型/未上线在 opening 中存在，但 turn1 JD解析失败，turn2未产生 active facts；turn3编辑时经历史恢复才抽出4条事实。补掉 pm 缺口恰恰需要处理历史，而本任务明确排除此类自动复活。不能以修 pm 为由悄悄解除边界。

## 必须拦截的反例

| 输入/状态 | 风险 |
|---|---|
| 旧 turn：“PaperTool 未上线”；后来更正或删除；历史恢复再次读旧 turn | raw_notes补全重新生成新的active ID，旧fact删除状态不能自动阻止新ID。 |
| “A只是原型。B未部署。”但模型只给A一个item并把整段放到A.raw_notes | 单条patch和完整note仍可将B的状态错误归给A。 |
| “助手建议：把 PaperTool 写成‘原型尚未上线’。” | 现有_candidate_evidence原样保留；直接词法补全会把建议当经历。 |
| “这是别人的示例：PaperTool只是原型，没有上线。” | 现有过滤只覆盖指定标签，不覆盖所有自然表达。该句经纯函数检查原样保留。 |
| “请保留PaperTool的‘未上线’，但这是范文，不是我的事实。” | 编辑命令/引用与反证混合，substring与项目名匹配仍不构成事实确认。 |
| “计划上线，但要等审批”；“支付模块，没上线” | 必须保留条件和对象，不能把识别到的短否定提升为整个项目状态。 |
| “实现没有结果的界面”；“检查没有匹配项的请求” | ‘没有’是界面/输入类别，不是未完成工作；不能补为经历状态。 |

前3条资料类型反例通过 AST 调用现有_candidate_evidence得到原样结果；这是 proposed fallback 的风险证明，不声称当前系统已把这些字符串写成事实。原处理器还会依靠路由、模型和语义验证，新增纯词法晋升路径不能绕开这些约束。

## 最小必要前提

若之后明确扩大该窄修复范围，调用层至少应提供可验证的来源记录：本轮候选人消息身份/ID、明确资料类型、唯一经历归属；历史恢复必须独立关闭该兜底。补全还需以仍有效的本轮来源为依据、避开更正/删除/编辑命令，并沿用原子句与来源记录。缺任一项就不补，不将 raw_notes 全量升级为 writer 证据。

这需要触及调用层契约，超出本轮仅 fact_extractor + 新测试的文件边界。未提供一个默认关闭且永远不被生产调用的补丁冒充修复，也没有仅为证明实现而新增测试。

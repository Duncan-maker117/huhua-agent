# 个人求职流程测试与修复

日期：2026-10-02。使用 Banz 提供的极飞科技 AI 产品实习 JPG 和旧简历初稿，姓名、电话及邮箱脱敏。真实本地 API 和配置的 DeepSeek；独立浏览器与会话，原聊天未改动。Banz 在本任务明确授权“你全权的做”后继续测试和修复。

## 结果

本案例已走通 **JPG 上传 → 核对识别文字 → 解码 JD → 导入旧简历 → 生成待核对草稿 → 实时编辑 → 保存与刷新恢复 → 检查当前版本 → 导出 PDF / Word**。修改栏目标题、顺序、删除空实习栏目和加入来源中已有的作品账号均已实测。

产物是待核对草稿。三个项目的个人职责、联系方式、日期、技能与奖项尚未全部确认；没有补造这些事实，也没有把作品机制自动改成个人贡献。本例不代表招聘效果、ATS 兼容或生产发布已经验证。

## 实测记录

以下是单次观测，不是延迟承诺。SSE 的浏览器 `transport_chunks` 是读取到的网络片段数，不等于 token 数。

- JPG OCR：HTTP 200，约 **5.04 秒**，识别 **1124 字**，农业场景、评测及“优先”技术项保留。
- JD 解码：约 **22.03 秒**；这是完成结构校验后展示的结果，非内部推理流。
- 基线旧简历导入约 34.84 秒、明确生成约 24.32 秒，均无结构化数据。此失败记录保留。
- 修复后同材料导入约 0.017 秒，确定性解析；随后生成约 **2.19 秒**，进入 EVALUATING。
- 保存后的真实检查：HTTP 200；首段 **16.032 秒**，完成 **21.623 秒**，读到 **687 个网络片段**；Markdown 正常、无页面脚本错误，保存 revision 未变化。
- 90 秒预算的生产函数独立复测：首公开文字 35.627 秒、总 39.770 秒、1123 个公开内容片段，未超时或中断。该次是函数调用，不能计作浏览器 HTTP/SSE。
- 真实“导出简历”：当轮给出 `/resume` 链接，进入 EXPORT，没有新增个人事实。

专业回复准确读到当前的作品账号、空联系方式及 3 项目事实，指出个人角色、评测/文档证据和待核对信息缺口。独立语义复核未发现新增个人职责、技能、指标或地点/届别不合格的断言。专业检查的建议不会自动写入简历。

## 还值得讨论的优化

1. **“包装建议 → 核对并采用”**：现在建议是只读回复，需要本人核对后在表单修改。可做逐条原句/建议对照和采用入口；不能把模型措辞直接认定为本人事实。
2. **成稿更紧凑**：当前草稿保守保留原文，标题性短句也会成为 bullet。补齐本人动作后，把每个项目压到最有证据的 2–3 条，比继续扩 Prompt 更有价值。
3. **首段等待**：本例检查/解码仍可能等 16–36 秒。现有可见等待和中断已补上，之后应拿更多真实案例比较模型/上下文方案，再定延迟目标。
4. **记忆**：资料已收集，框架未接入。历史保存不等于长期偏好和事实记忆，仍需 Banz 选择写入、更正、归属和删除规则。

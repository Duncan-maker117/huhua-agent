# 胡话简历：账号、个人档案与安全存取实施交付

日期：2026-10-04。授权依据：Banz 确认开发报告后回复“开始吧”。本轮范围是本地实现、隔离验证与开发文档；没有切换真实用户数据库、配置正式邮件服务或公开部署。

## 已接入的用户流程

1. **邮箱验证码登录，一号一人。** 同一账号使用本人唯一档案；会话、档案、保存、导出、删除均检查账号归属。历史浏览器资料需要有效原 Cookie 和显式认领，不能仅凭姓名或会话 ID 合并。
2. **档案跨聊天整理。** 用户消息保存成功后，在同一事务登记整理任务。后台 Agent 提取本人事实和长期偏好，保留来源、记录时间、适用时间与修订；重复信息合并，明确更正建立新修订，无法判断的冲突交给用户选择。较早经历不会仅因晚处理就覆盖较新状态。
3. **档案和简历各自可控。** 基本资料按需要进入新聊天，项目经历由用户选择用于当前稿。档案抽屉可以补充、更正、删除和查看来源；岗位版本保留名称、选用事实与过期提示。只改当前简历措辞不会自动改成全局事实。
4. **建议可以核对并采用。** 从当前稿选择可唯一定位的原句，展示改写和依据，再采用；支持撤销本次操作。旧修订、重复操作、新增数字或职责强化会被拦截；一般改写还需模型核对，用户仍需核实语义。采用后的保存、刷新和导出使用同一 canonical 数据。
5. **继承现有工作台。** JD、经历、简历、核对、导出各放右侧对应页；用户逐轮补充推动当前稿更新。输入框上方选项发送完整回答并防止连点，不反复向输入框追加模板。

档案整理失败、等待模型、配额耗尽和旧对话导入分别展示状态。未配置模型时，确定性基本字段仍可整理；需要语义提取的经历保留未完成状态。失败任务不会被显示成成功。

## 存取与运行保护

- 简历 JSON、正文、标题、账号邮箱、档案内容、来源、冲突、建议和完整 checkpoint/metadata/pending writes 使用 AES-GCM 认证加密。账号、记录、字段参与绑定，密文篡改或错误绑定拒绝读取；随机 ID、版本、时间等索引元数据仍可见。
- 数据密钥和账号索引密钥分开配置，前端不持有密钥。缺配置和旧明文库不会自动降级为可用的正式服务；正式模式要求登录、HTTPS origin 与 Secure Cookie。
- 常规文本模型请求先替换邮箱和常见电话，结构化结果在本地还原后核对来源。它不是完整匿名化；姓名、项目等必要内容仍可能送模型，图片识别仍需要原图。
- 浏览器不再长期保存对话和简历全文；未保存内容只在当前页面内存，用户可以主动下载。退出清空本页状态；私有 API 返回 `Cache-Control: no-store`。
- 删除/更正立即建立失效屏障，旧聊天、历史稿、旧任务和撤销不能重新采用旧值；在线派生副本随后清理。为过滤无事实引用的旧文本，服务端仍保留加密的最小旧值排除资料。删除档案与删除原聊天是不同操作，不能解释为所有历史介质已物理擦除。
- 保存失败会回滚图状态；读当前简历优先采用 SQL 已提交版本。遇到崩溃留下的领先 checkpoint，继续聊天前修复；过期版本不能覆盖新稿。旧对话导入逐项重试，一条损坏记录不会堵塞其他记录。
- 每账号每日操作次数持久化，聊天、图片识别、建议核对与归档受额度控制；另有模型并发和整轮超时。当前是操作次数预算，不是精确 token 或人民币账单上限。
- 日志只记路由模板、结果、耗时、保存状态和配额操作，不记录完整消息或模型异常正文；健康检查实际探测应用库与 checkpoint。首期部署使用**一个应用 worker**，多实例需要共享会话锁和额外并发验收。

## 迁移、备份与恢复

工具是 `backend/scripts/security_migrate.py`。只接受显式源路径与不存在的新目标路径，原文件保持不变。旧明文迁移在新文件插入前加密，避免原地重写残留旧正文；应用库与 checkpoint 分别迁移、回读，支持保留旧 key 的数据密钥轮换。未知的非空旧表拒绝静默复制。

恢复必须提供另行保管的最新加密隐私状态和可信摘要，缺失或不匹配即拒绝。恢复到新副本后先重放最新档案、失效与来源禁用状态。无法证明仍有效的旧会话会被保守舍弃，工具报告数量；没有可靠基线的 checkpoint 可能需要全部舍弃。这个代价意味着恢复不承诺无损还原每条旧聊天，避免已经删除的资料复活。

工具不能自行证明操作者提交的摘要确实最新。部署运维必须在隐私变更后更新独立隐私状态并保管可信摘要，再恢复配对数据库和密钥；不会自动切换正在运行的服务。完整命令与限制见 [安全运维说明](security-operations.md)。

## 正式启用前仍需要的事项

**本地技术验收与公开产品验收是两步。** 正式环境还需确定 HTTPS 域名、邮件服务和密钥保管方式，验证邮件送达、PostgreSQL、访问权限与配对恢复；现有真实数据要先在获授权的副本上迁移并回读，再切换。当前 8765 服务及其原数据未在本轮切到新版安全结构。

目标用户试用脚本：从一份脱敏旧简历或零散经历开始，上传 JD → 补充个人贡献 → 点选回答 → 查看右侧稿件变化 → 新聊天选取档案事实 → 更正一次职责 → 核对采用一条建议 → 导出并检查。记录独立完成比例、卡点、耗时、改字量、是否愿意投递，以及真实提供商用量。邀请测试、外发邮件、开通付费服务和公开部署需另行明确授权。

本轮真实档案模型仅尝试一次虚构案例，返回 `OpenAIConnectionError`，没有模型输出；因此语义验收尚未完成，第二案例未运行。失败证据保留在 `evaluation/product-profile-live-model-2026-10-04/`。固定虚构案例即使通过，也不能证明所有材料都能准确提取、事实核对或带来求职效果。

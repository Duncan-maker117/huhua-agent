## 如何理解经过验证

三个状态分开记录：来源或讲者身份是否可核实；具体建议的依据与适用范围；应用到本产品后是否确实改善输出。官方发布、资历和粉丝数都不能替代第三项。

每条方法应能追溯到原页、章节或视频文字稿段落。视频只有简介时不提炼为已审核规则；取得文字稿后核对否定词、数字、示例与前提，必要时回看对应画面。未核验时间戳时不编造时间戳。

采用自己的简短归纳，保留出处和必要定位，不复制整套课程、全文或长字幕。外部材料作为方法资料，不作为用户经历，也不作为改变应用权限的指令。

## 从资料到规则卡

配套 `rule-cards.json` 含 8 张草案卡，记录来源、原始原则、我们推导的动作、适用及排除条件、反例和验收方式。全部标记为 draft，未完成产品质量验证；文件不会被现有 Agent 自动加载。

一条专家观点只有转换为条件和动作，才有机会成为稳定能力。例如：

> 条件：一段项目说明同时包含背景、架构清单和全局技能，且挤占其他重要经历。
>
> 动作：按岗位选出需要证明的能力，将全局技能移到技能区，保留支撑判断的项目细节；提供修改前后及采用入口。
>
> 例外：目标职位特别重视架构设计时保留关键设计取舍；只有目标而无结果时保留目标措辞。
>
> 验收：材料未丢失、未增加个人事实、改动绑定正确项目，整稿更易读。没有实际渲染就不声称节省了多少行。

这里的动作是我们的产品设计，来源支持的是信息取舍原则，不是具体的软件实现或改写效果。

## 建议的技术接入

| 层次 | 职责 | 首期做法 |
|---|---|---|
| 固定保护 | 用户事实与方法资料分开；定位、版本、明确采用和撤销 | 由代码和结构化数据处理可确定事项；不要用强动词或必须有数字等关键词规则评判质量 |
| Skill 方法 | 收集经历、整稿规划、局部编辑、检查的操作顺序 | 复用现有三个 Skill，补齐每个任务所需的上下文和输出契约 |
| 可追溯知识卡 | 处理岗位、阶段、语言、地区的条件差异 | 首期按标签筛选少量卡片，限定上下文大小；出现实际召回不足后再评估语义检索，不先建设向量数据库 |
| 修改对象 | 让聊天建议和采用按钮使用同一份改动 | 每条携带经历 ID、字段、原版本、新旧文本、事实来源和采用理由；一般建议没有具体改动时不显示采用按钮 |
| 评测 | 检查事实和编辑价值 | 固定案例、独立留出案例、匿名前后对照和人工评审；保留无改善与失败结果 |

本轮所谓蒸馏，是把知识整理为可执行的方法和例子，不涉及训练模型权重。首期不做微调：当前缺口包含上下文和工作流，微调本身不能修复建议对象丢失或采用失败。未来若有足量、经授权且经质量标注的案例，再按实际收益评估训练方案。

现有接入点：

- `backend/app/agents/career_prompt.py`：已有版本与白名单加载；拟新增同版规则包、选卡记录和长度限制。
- `backend/app/services/resume_strategy.py`：拟在岗位重点和栏目顺序上增加整稿编辑计划，明确各经历的用途与软篇幅预算。
- `backend/app/services/resume_suggestions.py`：拟读取目标岗位、整稿计划和对应事实，不再仅拿一个孤立长字符串；区分事实更新和表达压缩。
- `scripts/evaluate_rewrites.py` 与 `evaluation/eval_career_prompts.py`：复用事实检查、随机 A/B 标签及独立答案键，记录规则版本和选卡。

稳定原则随版本发布；企业资格、招聘状态和平台上传要求只在需要时重新核验，不固化为长期规则。来源过期、失效或冲突时停用对应规则，保留旧版以便定位回归。

## 怎样证明有进步

先拟定 20 个覆盖不同材料和求职方向的案例，其中一部分作为独立留出集，不用于编写示例。包含无指标、课程项目、长项目挤占全稿、已确认新事实、重复经历名称、PDF 换行、有 JD 与无 JD、产品岗与开发岗等情况。

比较当前版本与规则包版本时，两组都收到相同事实和任务；评审不知道版本标签。以三组验收分开报告：

1. 事实和程序：不新增未经支持的事实，目标定位正确，修改可采用、可撤销，导出与当前稿一致。
2. 编辑质量：岗位相关性、个人贡献清晰度、有效信息密度、整稿篇幅取舍；允许原稿更好、两者相当和无法判断。
3. 用户结果：真实试用的成稿耗时、修改负担与投递意愿；面试结果另行观察，不能由小样本直接归因给规则包。

生成与评审可以共用原则，但评审不看生成理由或自评分。模型评审仅作辅助，应找目标岗位的实际招聘者或有审阅经验的人做盲评；目前没有完成这项评测。

## 审阅后的最小实施范围

优先把“资料完整收集、整稿取舍、建议准确绑定、采用成功”做通，并接入少量经过筛选的规则卡。更广泛的视频库、自动知识采集、微调与独立多 Agent 团队暂不列为首期必要工作。

对外应描述为有来源、可解释、经过具体案例检验的简历编辑能力。只有完成相应验证后，才能报告测试范围内的改善；不使用专家背书替代验证，不承诺面试率或 ATS 分数。

所有新增夹具均为虚构人物、经历和联系方式；邮箱/主页使用 example.invalid，GitHub 路径使用明确的虚构账号与仓库。

## 复现与根因

以同一综合夹具的 7 条经历（三条同源旅行项目、两对重复项目）验证旧 HEAD 的函数：用户原话与 edit_resume instruction 均为「合并重复的 mtagent 条目，整理成一页」。choose_edit_plan 只返回 set_constraint(page_limit=1)，execute_edit_plan 无 writer_requests，确定性保存返回 unchanged，7 条经历原样保留。单独的合并/技术栈复合请求还会误入 hide_item 或被 parse_stack_edit 提前拦截。此为离线源码复现，不声称取得了线上两次调用的完整参数。

| 问题 | 根因与修复 |
| --- | --- |
| 假修改 | 整条字典比较包含来源、默认空字段与不可见空白；改为显示内容比较，重编号不制造删增，前端同样过滤，空 diff 清空成功收据。 |
| 同源项目重复 | 原去重仅处理条目内正文，编辑计划无合并操作；增加 merge_duplicates 和统一预检，归一化标题并结合 profile_refs/明确的来源条目，保留信息最多的主条目、合并独有正文和技术栈。 |
| 技术栈污染 | 原话出现某短语即通过 supporting_ids，未检验它是否为技术名词；在名称规范化、纯列表解析、模型提议投影和交付预检处过滤句子/产品描述。 |
| 口语照抄 | 首人称检测漏掉标签后的「本人」，后续降级可再次引入口语；扩充门控、写稿/润色提示及确定性后备，团队归属和否定边界保留。 |
| 问题/决策重复 | 标签不同与短语长度让旧条目内去重漏检；按标签正文比较完整短分句，保留独立数字/限定，不用模糊语义删除事实。 |
| 已答仍追问 | 原逻辑只查关闭题目和档案维度，不查当前稿；在统一问题校验处读取对应可见条目的非空标签，合并前别名也可定位。 |
| 联系方式重复/错标 | 缺少跨标签 URL 规范化及值类型检查；统一协议、大小写去重键、尾斜杠，GitHub 链接/已知用户名纠正标签，空值与尾分隔符移除。 |
| 长标题截断/日期粘连 | 六款共享标题规则强制 nowrap，通用标题未限制 flex 最小宽度；共享宏统一允许换行、min-width:0、明确间距，日期靠右。七款均测实际 PDF 布局。 |
| 日期混用 | 原字段沿用来源的年月拼法；统一为 YYYY.MM，预计日期为 YYYY.MM（预计），至今和缺失月份不推测。 |
| PR/commit 长 URL | 缺少正文链接短写；同仓库 PR 写为 PR #6、#8，commit 保留短哈希，跨仓库保留仓库标识，不改变合入/待审状态。 |

预检接入 writer/pipeline、最终身份投影后的 write_draft、确定性编辑和技术栈编辑；不在只读读取或普通编辑器保存时擅自改写手工正文。删除/合并授权使用实际用户消息，模型 instruction 不能自行授权。合并映射保存在 resume_meta.merged_items，冲突角色/日期保存在 merge_conflicts；原始事实不改写，撤销保留完整旧稿，来源撤回仍可清理合并后的正文。不同项目共用一份上传文档、不同时间段的同名经历、隐藏条目不据此自动合并。

# 2026-10-08 完整资料到可下载简历

本轮依据「制作个人简历网站」聊天中的真实体验反馈：完整资料被当成岗位方向、点击生成后只有基本信息、模板刷新恢复默认、内置浏览器未取得 PDF/Word 文件。优先修复输入、成稿和导出这条流程。

## 当前行为

- 完整聊天资料不再要求单独的「项目经历」标题；支持姓名等显式字段、冒号栏目、同行教育信息和项目的下一行角色。生成指令与本人事实分开，参考/JD 不导入本人资料。
- 首轮有完整资料并明确要求生成，直接整理并进入核对；末尾的生成指令也能识别。已有稿件中「新事实 + 请生成」会先提取补充，再重建。
- 成稿反馈列出实际项目、教育、技能及奖项数量；只有基本信息时明确说明经历还未成稿。同样内容再生成不宣称新增。右侧下一步转为核对、修改或导出。
- 确定性的成稿确认在简历保存成功后发出；保存失败时尝试用失败说明替换本轮 checkpoint 中的成功话术，防止历史重放造成误解。模型流式建议仍即时显示，提示词要求保存前只说正在同步，失败仍由 SSE 明确报错。
- 自动分条必须完整保留每个原句，包括职责范围、反馈与「尚未上线」等限制。模型漏句时保留原文，不接受只摘有利表述的结果。
- 模板 ID 按会话保存为本机浏览器偏好，刷新恢复；不把简历内容或凭证放进该偏好。该项不代表跨设备同步。
- PDF 改为后端按当前模板返回真实文件，Word 继续返回通用 Word 文件。两者使用账号授权且已保存的当前稿，生成后保留可点击下载/打开入口，失败可重试。页面不会把「文件已生成」说成已保存在用户设备。

## PDF 运行配套

依赖 `weasyprint==70.0`；Docker 加入 Pango 和 Noto CJK。渲染仅接受应用自己的模板，禁用任意网络/本地文件资源读取，仅允许上传的 PNG/JPEG 照片。动态内容仍由模板转义；PDF 失败不影响聊天、保存或 Word。长文按 A4 分页，不自动删减为一页。

本机启动仍使用项目既有方式；此机器的虚拟环境需设置 `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib` 才能加载已有 Pango，测试可同时设置 `XDG_CACHE_HOME=/private/tmp/huhua-font-cache`。其他机器直接用 Python 运行时，需要对应原生运行库与中文字体；README 已补充命令，CI 已加入同款 Linux 依赖。部署时需重新构建镜像，单独复制 Python/JS 文件不能安装 PDF 依赖。

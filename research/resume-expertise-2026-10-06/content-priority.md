# 简历内容优先级与直观呈现

2026-10-06 研究与产品设计草案，尚未实施。目标是让读者容易找出候选方向、资格、相关经历和个人贡献，并让用户理解 Agent 为什么保留、压缩或省略内容。

## 判断内容价值

先核实用途、岗位方向和职业阶段，再比较材料。不为教育、项目、技能设置固定百分比，也不把编辑优先级显示成录用概率。

我们拟采用四个判断维度：与目标任务的相关性、个人贡献是否明确、事实依据是否足够、与已有内容相比是否增加有效信息。事实未经支持时不能靠其他维度高分抵消；简历必需信息不能因为占篇幅而被删。结果使用“重点展开、保留简写、候补、省略、待核对”，附具体理由。

“省略”只影响当前投递版本，原材料仍可用于其他岗位版本或面试准备。用户可以锁定要保留的经历；容量冲突时解释代价，不擅自清掉锁定项。

## 栏目和信息的默认处理

下表是结合来源形成的编辑建议，不是招聘方公布的评分规则。

| 内容 | 默认处理 | 调整条件 |
|---|---|---|
| 姓名、有效联系方式、明确的求职方向 | 精简、容易找到 | 没有确定方向时不伪造；缺联系方式不妨碍先生成草稿，但投递前应提示 |
| 教育、专业、学历、毕业时间 | 校招资格信息清楚，学生通常靠前 | 相关工作经验更强时可后移；仍保留目标岗位明确要求的资格 |
| 相关实习、工作、项目 | 占主要篇幅，突出本人行动、决策、交付和已知结果 | 依据相关性和证据排序，项目不天然低于实习；同一项目投不同岗位可调整重点 |
| 技能、工具、语言 | 精选分组，便于扫描，与材料对应 | 目标岗位明确要求且本人有依据时保留；不用熟练度进度条代替实际证据 |
| 奖项、证书、课程 | 通常简写或合并 | 岗位所需证照、相关竞赛和有辨识度的成果可提高优先级；不能从证书名称推导实际技能 |
| 社团、志愿、自由职业、内容创作 | 有相关能力证据时保留 | 经历较少时可承担重要证明作用；不按“非正式工作”一律删除 |
| 个人简介 | 可选 | 能解释转行、复合背景或独特匹配时保留；复述求职意向、空泛自夸和长篇自传优先省略 |
| 课程清单、通用工具清单、重复职责、过旧细节 | 优先压缩 | 稀缺且直接相关的内容例外；不能只凭时间旧就删掉唯一关键证据 |
| 与岗位无关且无具体事例的自我评价 | 通常删除 | 团队合作、沟通等能力应尽量在真实经历中体现 |

不要把公司名气、学校名气或数字大小当作内容价值的唯一代理。课程项目、没有商业指标的作品，也可能提供清楚、相关、能说明个人贡献的证据。

## 直观呈现的目标

1. 顶部能找到候选方向、联系方法和关键资格；栏目标题描述内容，不用装饰性标题掩盖分类。
2. 经历标题、本人角色、时间和正文有稳定层级；时间格式一致，栏内通常按倒序，栏目顺序按相关性调整。
3. 每个要点集中表达一个有价值的信息；重要经历可展开，次要经历可以只有一条，不强制所有项目凑相同条数。
4. 加粗用于少量重点，不整段加粗；颜色、图标、留白不应妨碍阅读，也不能成为唯一的信息区分方式。
5. 先删低价值内容和重复表达，再考虑换页；不靠不断缩小字号或压掉间距强塞一页。
6. 实际检查 PDF 和 Word：是否截断、标题孤立、跨页断裂、链接失效、文本抽取顺序错误；只检查 JSON 字数不能说明版面合格。

学生初稿可以优先尝试一页，经历充分或用途不同可以更多页。学术 CV、研究申请及要求完整经历的企业表单单独处理。照片、个人信息和版式习惯按地区与目标系统要求判断。

这些视觉目标仍需通过实际模板渲染、文本抽取和人工阅读验证；本轮没有生成新的简历样张或证明所有模板已满足。

## Agent 应解释取舍

用户不需要看内部规则编号，应看到类似下面的自然解释：

> 本版面向 AI 产品实习，重点保留能说明问题定义、方案取舍和交付的经历。两个项目里重复的工具名称移到技能区；缺乏具体例子的自我评价暂不放入。其他材料仍保留，可切换开发岗版本。

当用户询问“为什么只用了两个项目”，需要区分：文件未解析、经历未识别、已收集但未选入、选入后因篇幅压缩。它们不能共用一句“已导入”。建议提供逐文件结果和经历清单，在被省略的条目旁给出简短原因。

对“建议”的最低要求也要提高：明确位置、具体问题、岗位影响、修改前后、被保留的事实与必要待核点。只有“更专业”“更有说服力”而看不到实际信息改善，不算合格建议。允许判断原稿更好或无需修改。

## 正常但需要不同路径的情况

| 情况 | 应有行为 |
|---|---|
| 没有 JD，有岗位方向 | 先做能力展示版，允许之后定向；不反复索要 JD |
| 没有实习或量化结果 | 从课设、项目、活动和交付物找证据，不凭空补商业指标 |
| 经历太多 | 收集完整，选择重点，候补保留；不等于只解析前几项 |
| 资料极少 | 先确认可用事实，仅问会改变成稿的一两项；允许暂存不完整草稿 |
| 转行、经历跨度大 | 提取可迁移能力，可用短简介解释方向；不升级旧职责 |
| 同时想投产品和开发 | 保持同一事实底稿，分别形成岗位版本，避免混为一份万能简历 |
| 没回答追问，要求先出稿 | 用已有事实完成可用范围，将必要缺口独立标明，不反复卡住 |
| 用户要求保留某经历 | 锁定条目，必要时压缩其他内容或说明增加页数的取舍 |
| 原稿已不错、改写无改善 | 保留原稿，说明无需改；不为了产出建议制造问题 |
| 多人材料、参考简历、JD 混在附件中 | 先识别材料用途；归属不明确时不写入本人档案，询问最小必要问题 |

## 来源与验收

- [Princeton Resume Guide](https://careerdevelopment.princeton.edu/document/673)：13 页官方 PDF，已读原则、工作表与示例；支持按读者选材和展示个人贡献。美国高校语境，不提供通用百分比权重。
- [MIT Erik Pavesic 低年级简历指南](https://capd.mit.edu/blog/2023/09/01/enhance-your-resume-a-guide-for-first-year-undergraduates/)：已读全文，重点是 Content、Skills、Formatting、Organization；教育位置、技能呈现与条目数量随阶段和内容调整。URL 日期 2023-09-01，不把大一学生建议原样用于所有用户。
- [MIT 简历视频官方文字稿](https://capd.mit.edu/resources/career-toolkit-crafting-an-effective-resume/)：已读全文，支持保留材料母版、删减不相关细节和保持可读性；未观看视频画面。个人简介必写或必删不在这些资料的统一结论内，上述处理为我们的编辑建议。

拟议验收：相同事实投不同岗位时重点合理变化、无事实扩大；所有原始经历均有收集或未识别说明；重要信息在导出中易于找到；篇幅减少来自有效取舍；保留原稿和用户锁定内容的路径可用。采用匿名前后对照和实际渲染，不以模型单一总分代替验证。

# 胡话简历 MCP 开发报告

> 2026-10-14 · 基于线上 `20261013-2`（GitHub main `36d61fc`）· 状态：方案待确认，未动代码

## 0. 结论

**做一个远程 MCP 服务，挂在现有站点的 `https://resume.yikuaibanz.cn/mcp` 上。**

它的作用是让 Claude Code、Cursor、Codex、Claude Desktop 这类 AI 客户端可以直接读写用户的「个人档案」，并且能出一份一页、不编造的简历。

**MCP 只提供"规则和事实"，写作交给客户端自己的模型。**

我们手里真正值钱、别人难以复制的有三样：
- 加密的个人事实档案；
- 一页排版测量引擎；
- 事实核验。

这三样做成工具后都是确定性的，成本很低，也不消耗我们的 DeepSeek 额度。我们自己的写作流程（方案卡 → 追问 → 成稿）先不暴露，放到第三期，并且要加额度限制。

**最关键的一条设计：AI 客户端写进来的内容，不能直接变成"用户事实"。**

现有代码里已经有一条不变量：`source_kind="ai"` 的来源不进档案。MCP 写入要沿用这条规则。具体做法：
1. 客户端提交的内容先进「待确认收件箱」；
2. 用户在网页「信息确认」里点了确认，才转成 `manual` 来源进入档案。

这也是这个产品叫"胡话"、却主打"不编造"的立身之本。

**分三期：**

| 期 | 内容 | 能用的客户端 | 估时 |
|---|---|---|---|
| M1 | 个人访问令牌 + 只读工具 + 排版测量 + 导出 | Claude Code / Cursor / Codex（支持自定义 Header） | 2–3 天 |
| M2 | 待确认收件箱 + 保存简历版本 + 事实核验 | 同上 | 2–3 天 |
| M3 | OAuth 2.1 授权、托管写作工具（有额度） | 加上 claude.ai / Claude Desktop 连接器 | 4–5 天 |

## 1. 为什么值得做

1. **杀手级场景：在写代码的地方顺手记经历。**
   - 程序员在 Claude Code 里做完一个功能，说一句「把这个项目记到我的简历档案」。
   - Claude 读 git log 和 README，整理出项目名、技术栈、做了什么、结果，然后提交到收件箱。
   - 用户回到网页，点一下就确认了。
   - 原来写简历最痛的一步是"回忆经历"，这样就变成了平时的积累。这是网页版做不到的入口。
2. **在用户已经在用的 AI 里投简历。** 用户在 Claude 里看到一份 JD，可以直接让它调用胡话档案，产出一页 PDF，不用切到我们的网站。
3. **成本结构好。** 写作由客户端模型承担；我们只提供数据、测量和导出，每次调用花费在毫秒级、几乎零费用。
4. **作品集价值。** 一个"有事实边界的 MCP"本身就是个能讲清楚的 AI 产品设计案例：AI 写的内容不等于用户事实，需要人来把关。可以直接写进简历和面试。

## 2. 现有能力盘点（可直接复用）

| 能力 | 现有代码 | MCP 里怎么用 |
|---|---|---|
| 个人档案（加密、按账号隔离、有冲突/历史/撤销） | `services/profile_service.py`：`get_profile`、`get_context` | 只读工具。默认不返回联系方式 |
| 档案写入不变量（AI 来源不入档） | `enqueue_archive_event`：`source_kind ∉ {self, manual}` 一律跳过 | 收件箱的设计依据 |
| 等价判断与技能集合 | `services/profile_equivalence.py` | 收件箱去重，换个说法不重复提示 |
| 一页排版测量（density 0–3） | `services/resume_capacity.py::measure_rendered_pages` | `resume_measure` 工具，返回页数和溢出行数 |
| 模板渲染、PDF/Word 导出 | `api/resume.py` 的 render/export、`services/renderer.py` | `resume_export` 工具，返回短时下载链接 |
| 事实核验（先词法初筛，再语义核验） | `services/fact_guard.py::guard_bullets` | `resume_check_facts` 工具。M2 只做词法初筛，免费 |
| 简历版本与对话 | `session_store`、`conversation_store`、`/api/resume/current` | `resume_save` 写成一个网页里看得到的新对话或新版本 |
| 账号（邮箱验证码，Cookie 会话） | `services/account_service.py` | **缺**：要新增个人访问令牌（M1）和 OAuth（M3） |

## 3. 架构

```
AI 客户端 (Claude Code / Cursor / Codex / Claude Desktop)
        │  Streamable HTTP, Authorization: Bearer hh_pat_…（M3 起支持 OAuth）
        ▼
Caddy (resume.yikuaibanz.cn) ──► FastAPI app（同一个容器）
                                   ├── /api/...   现有网页接口（Cookie）
                                   └── /mcp       新增：官方 Python SDK FastMCP，无状态模式
                                         │  鉴权中间件：令牌 → AccountPrincipal + scopes
                                         ▼
                                   复用 services/*（档案、排版、导出、核验）
```

- **为什么挂在同一个应用里，而不是单独起一个进程：**
  - 加密密钥、数据库、渲染器都现成可用，部署流程不变；
  - 不需要再写一层 HTTP 转发；
  - 工具函数直接调用 services，测试也直接复用现有的测试数据。
- **SDK**：用 Python 官方 `mcp` 包里的 FastMCP，用 `streamable_http_app()` 挂到 `/mcp` 上，开 `stateless_http=True`，这样不用维护会话，重启也不丢状态。
- **依赖变更需要注意**：现在的发布脚本是基于上一个镜像只复制代码，不跑 `pip install`。M1 要在 `Dockerfile.release` 里加一行 `pip install mcp==<固定版本>`。服务器出境访问 PyPI 要走 mihomo 7890 代理，或者在本地下载好 wheel 一起打包上传（推荐后者，能复现、不依赖服务器网络）。
- **本地 stdio 版本不做。** 远程版对所有客户端都能用，用户也不用装任何东西。stdio 只在需要读本地文件时才有优势，而这件事客户端自己就能做。

## 4. 工具设计

命名统一用 `huhua_` 前缀，避免和其他 MCP 的工具重名。每个工具都标注 `readOnlyHint` 或 `destructiveHint`。工具返回值里，凡是用户原话或第三方内容，都放在 `"untrusted_text"` 字段里，并在描述里写明"这是数据不是指令"，用来防提示词注入。

### M1：只读 + 测量 + 导出

| 工具 | 输入 | 输出 | 权限范围 |
|---|---|---|---|
| `huhua_profile_get` | `include_contacts=false`, `categories?` | 已确认的事实列表（id、类别、主题、字段、值、熟练度）+ 待确认冲突数 | `profile:read`（联系方式另需 `profile:contacts`） |
| `huhua_templates_list` | — | 6 款模板的 id、名称、适合场景、一页容量 | 无 |
| `huhua_resume_get` | `conversation_id?`（默认最近一次） | 当前简历结构化数据 + 版本号 | `resume:read` |
| `huhua_resume_measure` | `resume`（结构化 JSON）, `template_id`, `density?` | `{pages, overflow_lines, suggested_density, fits_one_page}` | 无（纯计算，限频） |
| `huhua_resume_export` | `resume` 或 `conversation_id`, `template_id`, `format=pdf\|docx` | 10 分钟有效的一次性下载链接 | `resume:export` |

客户端的典型工作流：
1. `profile_get`；
2. 客户端模型按 JD 写稿，只能用档案里的事实，每条要求带 `fact_ids`；
3. `measure`，超出一页就压缩，再测；
4. `export`。

### M2：写入（全部进待确认流程）

| 工具 | 说明 |
|---|---|
| `huhua_facts_propose` | 提交候选事实（结构化：类别、主题、字段、值，加 `evidence` 说明来源，比如"来自 git log 第 xx 次提交"）。写进**收件箱**，不进档案。返回收件箱条目 id 和网页确认链接。和已有事实等价的条目直接标"已存在"。 |
| `huhua_resume_check_facts` | 输入简历要点 + 引用的 `fact_ids`，用 `fact_guard` 的词法初筛返回：新出现的数字、工具、身份词、没有引用的说法。不调用模型。 |
| `huhua_resume_save` | 把一份简历存成网页里的新对话或新版本，标记来源是 `mcp`。保存前强制跑一遍 `check_facts`；有问题的要点存为"待核对"，并在网页「核对」标签里显示。 |

**收件箱**（新表 `profile_inbox`，加密存储，和现有表的风格一致）：
- 状态有四种：`pending → accepted / rejected / expired`，30 天后过期。
- 网页「信息确认」面板里新增一组「来自 AI 助手的建议」。
- 用户可以对每条点「确认 / 改一下再确认 / 不要」。
- 确认时用 `source_kind="manual"` 走现有的 `enqueue_archive_event` 入档，复用现有的冲突、等价判断和撤销逻辑。
- 设计原则："AI 不能替用户作证"。这里不新开任何绕过方式。

### M3：托管写作（可选，要计费或限额）

`huhua_tailor_draft(jd_text)` 调用我们自己的 PR8 流程，直接产出方案卡和初稿。它消耗 DeepSeek 额度，所以：
- 每个账号每天 N 次；
- 只给已登录的账号；
- 走异步任务，返回任务 id，客户端再轮询结果。

先看 M1、M2 的实际使用情况，再决定要不要做。

### 资源和提示词模板

- 资源：
  - `huhua://profile`（等同于 `profile_get`，方便客户端直接引用）；
  - `huhua://templates/{id}/preview.png`（模板缩略图）。
- 提示词模板：
  - `tailor_resume_for_jd(jd)`：把"只用档案事实、每条带 fact_ids、先测量再导出"的纪律写成固定提示词。
  - `log_project_to_profile(repo_path?)`：指导客户端从仓库提取经历，再调用 `facts_propose`。

## 5. 鉴权与安全

| 项 | 方案 |
|---|---|
| M1 鉴权 | 用户在网页「个人档案 → 连接 AI 助手」里生成**个人访问令牌**，格式是 `hh_pat_` + 32 字节随机数。只显示一次，库里只存 sha256（复用 `AccountSession` 的做法）。可以设名称、权限范围、过期时间（默认 90 天），可以随时吊销，并显示最后使用时间。 |
| M3 鉴权 | OAuth 2.1 + PKCE。`/mcp` 返回 `WWW-Authenticate` 头，指向受保护资源元数据（`/.well-known/oauth-protected-resource`）。授权服务器复用邮箱验证码登录，客户端注册支持动态注册。claude.ai 和 Claude Desktop 的连接器要求走这个流程。 |
| 权限范围 | `profile:read`、`profile:contacts`、`profile:propose`、`resume:read`、`resume:write`、`resume:export`。令牌默认不带 `profile:contacts`。 |
| 游客 | 不开放。MCP 必须登录，因为游客数据 24 小时就清理，而且没法鉴权。 |
| 限频 | 每个令牌 60 次/分钟；`measure`、`export` 每分钟 10 次（渲染和测页占 CPU）；`propose` 每天 200 条。 |
| 审计 | 每次工具调用记一条：令牌 id、工具名、耗时、结果码。**不记参数内容**。用户在网页上能看到最近 50 次调用。 |
| 提示词注入 | 档案里的值和 JD 都是用户或第三方文本，工具描述和返回结构里明确标成数据。写入类工具不接受"指令性"字段，`propose` 只进收件箱，最坏情况就是多出几条要人工拒绝的建议。 |
| 下载链接 | 签名、一次性、10 分钟有效，路径不暴露账号 id。 |
| CORS 与来源 | `/mcp` 不接受浏览器 Cookie 鉴权，只认 Bearer，防止跨站请求伪造。 |

## 6. 改动清单（M1 + M2）

**后端**
- `backend/app/mcp/server.py`：新建，FastMCP 实例 + 工具定义，工具里只做参数校验和调用 services。
- `backend/app/mcp/auth.py`：新建，Bearer 令牌 → `AccountPrincipal` + 权限范围，加限频。
- `backend/app/models/account.py`：新增 `PersonalAccessToken` 表（`token_hash`、`account_id`、`name`、`scopes`、`expires_at`、`last_used_at`、`revoked_at`）。
- `backend/app/models/profile.py`：新增 `ProfileInbox` 表（加密载荷）。
- `backend/app/services/profile_service.py`：加 `propose_to_inbox` 和 `accept_inbox_item`，后者走 `enqueue_archive_event(..., source_kind="manual")`。
- `backend/app/api/account.py`：令牌的增、列、吊销接口，只认 Cookie 登录态。
- `backend/main.py`：挂载 `/mcp`；`lifespan` 里启动 MCP 的 session manager。
- 数据库迁移：两张新表，`schema_versions` 加 1。**这是本项目第一次带 schema 变更的发布**，演练脚本要加一步：在线上库副本上迁移，再回滚验证。

**前端**
- 档案面板：「连接 AI 助手」分区，可以生成或吊销令牌，并附一键复制的接入配置：
  - Claude Code：`claude mcp add --transport http huhua https://resume.yikuaibanz.cn/mcp --header "Authorization: Bearer …"`
  - Cursor / Codex：给出对应的 JSON 或 TOML 片段。
- 「信息确认」面板：新增「来自 AI 助手的建议」分组。

**测试**
- 工具层：用 SDK 自带的内存客户端，逐个调用工具，断言返回的结构和权限范围拒绝的情况。
- 不变量：`facts_propose` 之后 `profile_get` 里看不到新事实；`accept` 之后才能看到；来源记为 `manual`。
- 安全：吊销或过期的令牌返回 401；权限范围不够返回 403；Cookie 访问 `/mcp` 被拒；默认不返回联系方式。
- 端到端：本地起服务，用 MCP Inspector 加 Claude Code 实际连上，跑第 7 节的两条验收路径。

## 7. 验收标准

1. **记经历**：在本仓库里用 Claude Code 说「把胡话简历这个项目记到我的档案」。
   - 收件箱里出现 ≥3 条带 evidence 的候选；
   - 网页上确认后，进入档案；
   - 全程档案里没有出现未经确认的内容。
2. **按 JD 出简历**：用虚构账号和公开 JD，在 Claude Code 里调用 `profile_get → measure → export`。
   - 拿到 1 页 PDF；
   - `check_facts` 零个新数字或工具；
   - 我们这边 DeepSeek 调用数为 0。
3. **性能**：`profile_get` 的 P95 < 200ms；`measure` 的 P95 < 2s，以服务器上现有测页耗时 0.15–1.1s 为基准。
4. **安全**：第 6 节的安全测试全过；线上抽查审计日志，不含任何参数原文。
5. **回归**：现有 1355 项测试全过；网页登录、对话、导出不受影响。

## 10. 实现约束（2026-10-14 用户批准 M1+M2、收件箱人工确认、Codex 实现）

- SDK：本地 .venv 已装 `mcp==2.3.0`（2.x：FastMCP 已改名 `MCPServer`，`from mcp.server.mcpserver import MCPServer`；以已安装包源码与 `.venv/lib/python3.13/site-packages/mcp` 为准，不要凭 1.x 记忆写）。requirements.txt 固定 `mcp==2.3.0`。服务器镜像 Python 3.12，需兼容。
- 新表只做增量（`personal_access_tokens`、`profile_inbox`），由现有 `Base.metadata.create_all` 创建；**不提升 SCHEMA_VERSION**（提升会让启动拒绝旧库）。旧表不改列。
- `/mcp` 只认 `Authorization: Bearer hh_pat_…`，忽略 Cookie；无/错/吊销/过期令牌 401 并带 `WWW-Authenticate: Bearer`；scope 不足的工具调用返回工具错误（不泄露数据）。
- 工具实现只做参数校验+调用 services；同步阻塞的渲染/测页走 `asyncio.to_thread`。
- 联系方式（basic 的 phone/email/link/github/website）无 `profile:contacts` 时不返回，`resume_get`/`export` 同理在无该 scope 时用占位符（与游客脱敏一致的做法，若现有代码有脱敏函数则复用）。
- 下载链接：`/api/mcp-download/{token}`，token 为随机 32 字节，服务端内存或 DB 存 10 分钟、一次性；内容生成时即渲染好存临时目录或内存（≤5MB）。
- 审计：新表或复用日志均可，但只记 token_id、tool、耗时、状态码，不记参数；网页「连接 AI 助手」显示最近 50 次。
- 限频：进程内令牌桶即可（单容器），按 token_id。

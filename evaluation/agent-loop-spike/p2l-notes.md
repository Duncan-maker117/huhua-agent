## 修改文件与规则

1. `backend/app/services/fact_corrections.py`：新增 `merge_new_experience_identities`，作为 P2h 强证据规则的补充。仅检查经历栏目，不自动合并教育。
   - 当前栏目恰有两条：一个已知占位名、一个真实名；两条 item_id 都不存在于抽取前状态，不能借用旧条目。
   - 真实名必须逐字出现在本条用户的本人材料中；事实均须来自当前 turn 的 chat，附加 sources 也不能混入其他消息或导入来源。缺失可验证来源时不猜。
   - 逐项核对 `start_date/end_date/date` 的条目字段及 active 字段事实。占位无日期或与目标相同才通过；单条内部存在冲突也拒绝。
   - 多候选（包括原有的第三条）、跨消息、跨栏目、独立真实名称、日期冲突、名称未在当前原文出现，均不能触发这条新增规则。
   - 复用 `apply_experience_merges`：保留真实名 item_id、原 fact IDs、source_quote、sources、否定限制、原始笔记与链接，记录来源占位 item 的 `merged_from`。没有引入模糊名称相似度、writer 跨条目引用或新模型判断。
2. `backend/app/agents/orchestrator_tools.py`：在 `record_facts` 应用补丁后、持久化前执行新增合并。P2h 原 `_bind_campus_identity` 强证据路径保留原样，其全部既有合并/拒绝断言不变。
   - `write_draft` 发现同栏目仍有“可见真实名无做法 + 占位名有有效做法”时返回 `status=insufficient`、`code=experience_identity_unresolved`、明确原因和一个“这些条目是同一段经历吗”澄清问题。
   - 同轮复用现有 `ask_user` 适配器附卡并停止写作；卡进入 guidance 和最终回复，不依赖模型再决定一次。没有写入新正文、没有移动不确定事实、没有自动选定多个候选的归属。
   - 已被方案隐藏的占位正文仍可能持有待确认事实；已隐藏的真实名目标不阻塞其他写稿。删除事实、只有限制、跨栏目、真实名已有做法时不触发。
   - 保留关闭维度、停止追问、共享追问预算、同轮一张卡和待确认方案限制；不能附卡时仍返回明确不足原因，并附 `followup_unavailable_reason`，不突破既有用户限制。
3. `backend/app/agents/resume_graph.py`：旧 collecting 的单消息抽取分配独立 turn_id，同步传给原有职责归属修正，再调用同一合并函数。名称核对使用 `_candidate_evidence`，参考材料中的名字不能成为本人经历的合并依据。
4. `tests/test_orchestrator_p2l.py`：新增 12 项离线回归（含多组子场景），直接读取冻结快照，使用真实 `apply_fact_patch`、持久化入口、writer/guard 管线与编排；抽取补丁冻结、writer 和编排模型均为离线桩。

没有改 writer、fact_guard、模型提示词、岗位手册、人物验收判定或前端；测试人物内容只存在于现有 fixture 和测试断言，没有注入生产提示或手册。

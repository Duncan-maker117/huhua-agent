# JD 解码与简历检查：资料依据和执行规则

核验日期：2026-10-02。面向中国求职、尤其校招的产品设计资料。本文给出方法与候选规则；未证明模型效果、ATS 通过率或面试转化率，也未接入任何服务。

## 一手来源

### JD-S01 — University of Michigan HR：How to Write Job Descriptions

[官方原文](https://hr.umich.edu/working-u-m/management-administration/compensation-classification/compensation-classification-tools-procedures/how-write-job-descriptions)

- **原文支持**：JD 包含岗位目的、主要职责及产出、技能与能力、最低要求、优先条件、工作条件；最低要求与优先条件应明确区分。工作职责应反映实际范围，夸大责任会造成问题。
- **对 Skill 的规则**：将 JD 分成“职责 / 必要条件 / 加分条件 / 工作条件”。每个结论保留原句；只把原文明示的 must、required、必须、要求等归为必要条件。不能把 preferred、加分项、优先变成硬性门槛。原文未分级的条目标记“要求级别未明确”。
- **对证据匹配的规则**：先把职责变成“将承担什么任务、需要什么能力、期待什么产出”，再找经历中的对应证据。关键词只作为检索入口。
- **不支持的推断**：该来源是美国大学的岗位编写指南，不是每个中国公司的招聘规则；不得据此补出 JD 没写的学历、专业、工作年限，也不能声称识别了招聘方的隐藏标准。

### JD-S02 — University of Michigan Career Center：Resume Resources

[官方原文](https://careercenter.umich.edu/article/resume-resources)

- **原文支持**：按具体机会调整简历；用行动、做了什么、如何做 / 为什么做 / 产生什么影响表达能力。AI 建议需核对准确性并保留个人表达。明确提供了把 JD 与简历对照、发现缺少哪些技能证据的用法。
- **对 Skill 的规则**：对应 JD 的每个核心要求，输出“已有证据 / 部分证据 / 尚无证据 / 信息不足”。解释对应的是哪一条经历及哪一句事实。不得将简历里没写解释成“用户一定不会”；可追问一条最能改变判断的信息。
- **对检查的规则**：优先查具体行动、负责范围、方法、成果或已完成产物；量化以已有事实为前提，没有指标就写清过程或交付物。
- **不支持的推断**：不能把美国本科常见的一页建议变成所有人强制要求；研究型履历和不同岗位可能有不同形式。该来源没有验证某个关键词密度、ATS 评分或中国校招成功率。

### JD-S03 — Greenhouse：Unsuccessful resume parse

[官方原文](https://support.greenhouse.io/hc/en-us/articles/200989175-Unsuccessful-resume-parse)；页面更新于 2026-03-02。

- **原文支持**：解析是把上传简历的信息填入候选人字段，可能失败或仅部分成功。该产品列举图片、复杂表格、页眉页脚、文本框、分栏等风险，要求人工更正 / 核对；列有该产品的 2.5 MB 解析限制。
- **对 Skill 的规则**：将“内容可读”“机器能提取文字”“字段顺序及归类是否正确”分开检查。先检测文件是否有文本层；导出后检查姓名、联系方式、组织、职位、时间能否按正确顺序提取。若只收到纯文本，不评价未知的版式或文件解析效果。
- **风险表达**：使用“该格式可能带来解析风险，需在目标申请系统确认”；没有真实解析结果时使用 `not_tested`。
- **不支持的推断**：不能声称所有 ATS 禁止照片、双栏或 PDF，不能将 Greenhouse 的大小限制施加到所有平台；解析失败也不等同于被拒绝。不能用应用内 JPG 识别能力推断投递平台能正确解析图片简历。

### JD-S04 — Greenhouse：Auto-reject

[官方原文](https://support.greenhouse.io/hc/en-us/articles/360000653472-Auto-reject)；页面更新于 2026-01-30。

- **原文支持**：雇主可以对申请问题的回答配置自动拒绝规则；其文档举的是岗位所需证照问题，支持问题类型为是 / 否、单选和多选。
- **对 Skill 的规则**：资格检查单独放在措辞优化之前，包括原文要求的毕业时间、证照、工作地点、到岗 / 实习时长等。能核验时给出满足、不满足、未知；不能核验时说明缺什么，不替用户填答案。
- **对检查的规则**：若用户报告拒绝，先区分未知原因、资格、申请表答案、解析问题与表达问题；不要看到拒绝就断言关键词不够。可以建议核对申请表自动填入的信息。
- **不支持的推断**：不能声称所有自动拒绝都由表单规则引起；不能反推出某个雇主私有规则，也不能承诺文案调整绕过资格条件。该文档没有通用 ATS 分数或“达到 80 分必过”依据。

### JD-S05 — 字节跳动 Seed：2027 届大模型人才校招（含实习）

[官方原文](https://seed.bytedance.com/zh/blog/bytedance-seed-2027-foundation-model-campus-recruitment-is-now-open-internships-included)；发表于 2026-04-01。

- **原文支持**：该具体项目把应届生对象写为 2026 年 9 月至 2027 年 8 月毕业的本科、硕士、博士；实习生对象为 2027 年 9 月及以后毕业的高校在读学生。
- **对 Skill 的规则**：解析并保留“公司、项目、招聘类型、毕业时间范围、学历、核验时间、来源”。同一校招活动含实习，不代表所有岗位都是正式应届岗；将 `employment_type` 与 `campus_year_label` 分开。
- **不支持的推断**：这是 Seed 特定招聘项目的公告，不能扩展为字节全公司、日常实习或全部中国公司的统一规则；公告本身不能证明某个具体岗位现在仍开放。岗位状态需查看具体职位页。

### JD-S06 — 腾讯音乐娱乐：2027 校园招聘 FAQ

[官方原文](https://join.tencentmusic.com/campus/)；2026-10-02 读取当前 FAQ。

- **原文支持**：其 2027 校招应届生窗口为 2026 年 1 月至 2027 年 12 月；中国内地以毕业证为准，港澳台和海外以学位证为准。页面要求选择“应届生”投递类型。
- **对 Skill 的规则**：同样叫“2027 校招”，公司窗口仍可能不同；不能只依据届别标签计算资格。用户提供具体毕业年月及项目后，才做区间比较，边界月份按原文明示条件处理。
- **不支持的推断**：TME 不等于腾讯全集团；该校招 FAQ 不代表所有实习 / 社招要求。不要把这条时间范围写成长期固定系统规则，应保留来源和日期，投递前复核。

## 建议写入 Skill / system prompt 的操作规则

以下是结合资料形成的**产品设计判断**，不是原文给出的模型评测结论。

1. **先核资格，再解释工作。** 限定招聘类型与来源，列出明示的硬条件；如果未知，只写未知。
2. **不要“解码”出隐藏事实。** JD 黑话解释可以讲常见可能含义，但必须与原文明示要求分栏，并标记待向招聘方核实。没有证据，不写“其实就是要你……”的确定判断。
3. **做逐条证据对齐。** `requirement → JD 原句 → 用户事实 / 原句 → match_status → missing_evidence → next_question`；任务、方法、产出比关键词重复更有判断价值。
4. **未出现不等于没有。** “简历未提供证据”与“用户不具备能力”必须分开；同义工具、可迁移经验最多标部分证据，并说明迁移前提。
5. **避免把匹配评价写成录用预测。** 若产品需要分数，明确它是自定义、可解释的证据覆盖指标；展示评分维度、权重、缺失信息及未核验资格，不能称为真实 ATS 分数、招聘方评分或面试概率。
6. **检查必须分能力范围。** 事实与前后一致性、岗位证据、清晰表达可以检查；文件版式、导出解析、外链可访问性、实际招聘状态，只有真正调用相应工具才标已验证。
7. **具体到修改位置。** 每条问题给 `原句 / 问题 / 为什么影响这个岗位 / 可执行修订或追问`；最多优先给 3 条最影响结果的问题，避免把无关个人信息当成普遍必填项。
8. **保留真实范围。** “参与”不能自动升级为“主导”；个人 Demo、课程作业、Mock、离线测试不能自动升级为上线、商业使用、真实用户或生产指标。
9. **查词汇也查结构。** 标准术语只在真实经历中有上下文地使用；禁止堆词、隐藏文字和往技能栏添加未使用的工具来制造匹配。
10. **效果用对照验证。** 对同一份匿名素材与 JD，比较普通通用 prompt 和专用系统 prompt + Skill：是否分清必要 / 优先，是否证据定位准确，是否追问有效，是否无事实升级，是否产物更具体。当前资料不能替代这项验证。

## 反例与候选回归用例

### JD-R01：优先条件被当成硬门槛

输入：JD 写“熟悉 Python；有 LangGraph 经验优先”。用户只给出 Python FastAPI 项目事实。

- 错误：断言用户“不符合岗位要求”，或将 LangGraph 加进技能栏后宣布已匹配。
- 合格：Python 有对应项目证据；LangGraph 是优先条件且目前未提供证据；如需要，只追问是否用过相关工作流框架或可迁移的状态管理实践。不能自行替用户确认技能。

### JD-R02：同届校招的资格窗口被固定化

输入：用户 2027 年 12 月毕业，要比较上面 Seed 应届生项目与 TME 2027 应届生项目。

- 错误：因为都是“2027 校招”就对两个项目均判符合，或将 Seed 实习归为正式校招。
- 合格：按这些已核验公告，Seed 应届窗口不含 2027 年 12 月，实习窗口包含该毕业时间但仍需具体实习岗位要求；TME 公布的应届时间范围包含 2027 年 12 月。明确公告日期，要求投递前复核具体职位。不能由此认定岗位现在仍开放或用户所有资格均满足。

### JR-R01：只读了文字却宣布 ATS 检查通过

输入：模型只收到 PDF 提取的简历文本，未知 PDF 布局；用户问“能过 ATS 吗”。

- 错误：返回 ATS 92 分、所有系统都兼容、必进人工筛选。
- 合格：给出已能检查的文字结构与岗位证据问题；文件版式 / 目标系统解析标未测试，建议实际核对上传后的字段；不输出通过保证。

### JR-R02：无量化事实时虚构影响

输入：用户说“自己做了一个课程问答 Demo，用 FastAPI；没有真实用户和评估数据”，JD 重视可落地能力。

- 错误：改成“主导上线知识库产品，服务 1,000+ 用户，准确率提升 30%”。
- 合格：写清个人 Demo、已实现功能和真实技术；追问测试方法、能展示的产物、负责范围。没有答案时允许先交付不含虚构指标的可用描述。

## 适用范围和维护

- 美国大学资料提供写作和职责结构方法；中国校招资格以中国招聘主体具体项目 / 职位原文为准。
- ATS 风险必须注明供应商范围与“未测试 / 实测”；投递平台政策可能变化，不能用旧规则作永久保证。
- 两份中国校招公告用于规则反例，不能转写成模型永远沿用的知识；后续具体求职需按岗位 URL 及当次时间复核。
- 引用全部为原始来源或官方文档，未采用第三方“关键词密度”“ATS 通过率”营销材料。Harvard AI 简历页搜索可读但直接打开返回 429，未用它承载本文件的新规则。

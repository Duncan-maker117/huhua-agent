# 产品经理（校招 / 实习，C 端 / B 端 / 策略）

## 筛选者看什么（按权重）
1. **问题定义能力**：能说清楚用户是谁、痛点是什么、怎么发现的。证据：用户访谈/问卷/数据分析得出的结论。弱证据："负责需求分析"。
2. **方案与取舍**：为什么做 A 不做 B，优先级怎么排。证据：需求池排序、砍掉的需求、方案对比。
3. **交付与推动**：PRD、原型、跟进开发测试、上线。证据：文档、原型、上线功能、协作的角色和人数。
4. **结果**：上线后的数据或反馈（转化、留存、使用率、满意度、效率）。
5. **行业/业务理解**：对目标业务（电商、内容、SaaS、本地生活等）的理解，竞品分析。
6. 数据能力：SQL、埋点、AB 测试（B 端/策略岗权重更高）。

## 学生能拿出的证据
实习中跟过的需求、校园产品/小程序、比赛方案、竞品分析报告、产品体验报告、自己的 side project、社团里组织过的线上工具。

## 成果口径
- 用户：覆盖人数、访谈/问卷样本数、日活/使用次数
- 转化与留存：点击率、转化率、留存率、完成率（必须带口径：谁、多长时间、对比什么）
- 效率：流程耗时、人工步骤、客服量
- 交付：PRD 份数/需求个数、上线功能数、迭代版本数
- 反馈：用户评价、被业务方采纳、评审结论

## 表达
- 推荐动词：调研、定义、梳理、设计、撰写、推动、协调、上线、复盘、验证
- 句式：**[发现问题/依据] → [本人方案动作] → [结果/产出]**
- B 端强调流程和效率，C 端强调用户和数据，策略强调指标和实验。
- 避免："负责产品全生命周期""具有良好的沟通能力"。

## 改写示例（方法演示）
- 原话：「在 xx 实习的时候写了几个需求文档，有一个是优化下单页的，后来上线了」
- 改写：「撰写下单页优化需求 PRD，该需求已上线」
- 不能写：「负责」（原话没说需求归属本人）、「跟进研发测试」（原话没说）。
- 追问："这个需求是你主要负责的吗？上线前你有没有跟开发、测试对接？为什么要优化下单页——是数据看到流失，还是用户反馈？上线后有没有看转化变化？"

## 高价值追问
- "这个需求是怎么来的？谁提的、依据是什么？"
- "你在里面具体做了什么——写文档、画原型、跟开发、还是做了决策？"
- "上线后数据/反馈怎样？哪怕是'大家说好用'也行。"
- "有没有你主动砍掉或调整的需求？为什么？"

## 常见坑
- 把团队/业务方的决策写成本人决策；"参与"写成"主导"。
- 只有"写了 PRD"，没有问题和结果。

# PR8 主线流程：用户掌舵、先定方案再成稿

日期：2026-10-11
来源：上线后首次真人试用（自然选择 AI 产品实习 case，原始对话存 `cases-private/`，不入库）。

## 1. 问题

试用暴露的问题分两类。

**体验层**
- 用户说"你好"，只回"请把目标岗位的招聘JD粘贴给我"（`resume_graph.py` JD_INPUT 提示词写死）。冷、没说明能做什么。
- 简历结构完全由 agent 决定，用户没有选择权；"这版的思路"是模板句，摘半句原文。
- 用户问"你觉得怎么说更好"，系统没回答，直接又改一版（征求意见被当成改稿）。
- 老用户档案里已有经历，仍然被当新人从头问。

**数据层（bug）**
- B1 开源贡献被塞成项目，标题"自己 | 原型"；用户纠正"这是开源贡献，和项目经历一个标题"后标题不变，还追问"「自己」是独立完成还是团队协作"。根因：没有"开源贡献 / 竞赛荣誉"栏目类型。
- B2 竞赛荣誉整块丢失。
- B3 教育被压成"就读于哈尔滨商业大学（本科）"，专业、起止时间、奖学金丢失；页头丢 GitHub、个人主页、可实习时间。
- B4 用户说"20 次"（简历任务）被写成"20 次调用"。
- B5 半句话（"三个人的团队……分别是"）整句被拒收，"3 人团队、本人负责 Agent 设计"随之丢失。
- B6 与目标公司核心问题（长期记忆）最相关的一条经历（VoiceMem PR #10：记忆跨语言污染）没进简历——没有主线。

## 2. 设计原则

1. **AI 提案，用户拍板**：主线、栏目、取舍这类决定都以"方案卡"呈现：一个推荐 + 1–2 个备选，一键确认或用一句话改。agent 不再静默决定结构。
2. **一次给足，少问**：鼓励一次粘贴整段材料 / 旧简历 / 截图；每轮最多问一个问题，且只问会改变简历的问题。
3. **档案是资产**：事实跨会话保存；老用户不重复收集。
4. **先主线，后成文**：成稿前先有一句话定位和主线（thesis），每段经历写 / 压缩 / 不写都有理由。
5. **阶段可见、可跳、可回退**：不是死板的向导。任何时候贴 JD、贴材料都能接住；右侧标签显示当前阶段。

## 3. 流程

```
新用户:  开场 → 建档 → 定目标 → 补证据(可跳) → 定方案 → 成稿 → 打磨 → 导出
老用户:  欢迎回来 → 贴 JD → 定方案 → 成稿 → 打磨 → 导出
```

| 阶段 | 做什么 | 关键交互 |
|---|---|---|
| 开场 | 寒暄、三行说明能做什么、识别新老用户 | 入口按钮：「上传旧简历/材料」「贴目标 JD」「从零聊起」；老用户：「贴新 JD 出一版」「继续上次」「更新档案」 |
| 建档 | 批量吃材料（文字/PDF/DOCX/截图）抽事实：基本信息、教育、实习、项目、开源贡献、竞赛荣誉、技能 | 回一张"档案卡"：识别到哪些、缺哪些关键项；基本信息缺失时一次问齐 |
| 定目标 | 解读 JD + 用户给的公司信息（公司在解决什么问题） | 已有，保留"读岗位" |
| 补证据 | 对照 JD 找缺证据的要求，一张卡最多 3 个问题，答任意一个或跳过 | 已有追问，改为按缺口排序 |
| **定方案**（新增） | 生成方案：一句话定位、主线、栏目顺序、每段经历 写/压缩/不写 + 理由、预计页数 | 方案卡：推荐 + 备选；「按推荐写」一键确认；也可说"把开源贡献放前面" |
| 成稿 | writer 严格按已确认方案写；"这版的思路"由方案生成 | — |
| 打磨 | 核对清单 + 用户精改；征求意见类问题给 2–3 个可选说法而不是直接改 | 后续可加"面试官挑刺" |
| 导出 | PDF / Word | 已有 |

## 4. 分阶段实现

每阶段：Codex（gpt-6.1-sol, xhigh）实现 → Claude 审 diff、跑全量测试 → 涉及写作质量的跑 benchmark 对比 → 记录 §9 并提交。

### P1 对话意图与开场（不影响写作质量，直接做）
- 开场：寒暄 / 无实质内容的消息，回复简短友好的自我介绍 + 能做什么 + 下一步入口；老用户（有档案事实）用名字欢迎并说明档案概况（N 段经历）。
- router 新增意图：`greeting`（寒暄）、`advice`（征求意见："怎么说更好""你觉得呢"）。`advice` 回复 2–3 个可选说法并说明区别，**不改稿**。
- B5：半句话不再整句拒收；能确认的部分照常记录，只对不完整的尾巴提示补充。
- 验收：单测覆盖三种意图路由；"你好"不再触发要 JD 的固定句；"你觉得怎么说更好"不产生新版本。

### P2 栏目与数据保真（B1–B4）
- 新增栏目类型：开源贡献（open_source：项目名、链接/PR 号、贡献内容）、竞赛荣誉（awards：名称、级别、时间）。抽取、档案、canonical、模板渲染、Word 导出全链路支持。
- 页头支持链接（GitHub、个人主页）、可实习时间。
- 教育条目保留学校、专业、学历、起止时间、奖项；writer 不得把教育压成一句话。
- 用户把条目改到别的栏目（"这是开源贡献"）要能执行：移动栏目并改标题。
- B4：数量词保留原单位（次/人/个），不得换成别的计量。
- 验收：用虚构资料复现 B1–B4 的单测 / 集成测试。

### P3 定方案（主线，影响写作质量，需 benchmark）
- 新增 plan 步骤：输入档案事实 + JD 解读 + 公司信息 → 输出方案（定位句、主线、栏目顺序、经历取舍 + 理由、备选方案）。复用现有 match_plan，拆成"先给用户看的方案"和"按方案写"两步。
- 前端方案卡：推荐 / 备选切换、「按推荐写」、自由文字修改。
- writer 严格按确认的方案；"这版的思路"由方案生成。
- 用户已确认方案后，后续改稿沿用方案，除非用户改方案。
- 验收：benchmark 现有 case + 新增 case（自然选择）不退步；新 case 要求 VoiceMem 类最相关经历进稿、开源/荣誉栏目存在、教育完整。

### P4 老用户快速路径
- 有档案时贴 JD → 直接出方案卡 → 确认即成稿；只在缺关键证据时追问。
- 验收：老用户从贴 JD 到首稿，用户操作 ≤ 2 次。

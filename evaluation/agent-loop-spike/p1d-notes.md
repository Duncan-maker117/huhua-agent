# 第十七批 d：粘贴材料事实归属与 DSML 回归

日期：2026-10-19。分支 `batch17d`，起始 HEAD `ae9547f`（集成分支 `batch17b`）。

## 根因与证据边界

本轮没有调用真实模型，不能确认真实回放时模型的原始 JSON 是否已经包含错误名称。用户材料只保存在 `tests/fixtures/batch17d_upload.txt`；测试中的模型 JSON 是按抽取器协议构造的桩，不是实测模型响应。

离线已证明，即使模型桩只返回一个正确具名的项目，原代码仍会生成额外的“不是”项目：

1. `parse_existing_resume` 对这类逐行短标签材料返回 `None`，旧 `collecting_node` 和编排 `record_facts` 都进入 `extract_facts_patch`。
2. `experience_subjects.explicit_subject_spans` 只把项目标题当作归属范围，在第一个换行结束；后面的角色、具体工作、范围行没有稳定的显式主体。
3. 抽取器把同一模型条目的 `source_quote` 用换行连接为 `item_evidence`。`candidate_language.literal_item_name` 的“开发 + 名称 + 项目”等模式使用 `\s*`，允许跨行；相邻事实中的动作词与后续否定句组合后，可把“不是”识别为名称。`safe_item_name` 原先只排除部分口语句式，接受了该名称；确定性识别结果又优先于模型原名称。
4. 标题识别出的正确项目与错误名称得到不同 ID。后续按 ID / 规范名称合并无法判断它们相同，`apply_fact_patch` 和 `normalize_fact_store` 把两项保留下来。这里应修归属和名称识别，不能在落库后盲目合并任意两个项目。
5. 旧的漏抽恢复主要覆盖动作或少量限制，对分行材料中的本地执行、前提和否定范围覆盖不足。

修复前的离线失败记录见 `p1d-facts-before.log`（本地忽略日志）：正常模型桩和故意拆项桩均出现两个项目；稀疏/空桩丢角色与部分事实。日志里的早期 collecting `AttributeError` 属于测试替身未适配模型构造器，见失败做法。

## 改动文件

- `backend/app/services/candidate_language.py`：阻止项目名称模式跨换行捕获；名称检查拒绝否定及职责边界句。新增仅供事实抽取/名称校验使用的 `experience_constraint`，识别纯否定动作、第三方负责、非负责人等限制，使其保存为 `status_limit`，不成为本人职责。原 `constraint_only` / 正文清理规则保持不变，正文需要展示的上线、压测和分工范围继续保留。
- `backend/app/services/experience_subjects.py`：显式项目/工作/校园条目允许紧邻的角色、职务、具体工作、工作内容、职责、范围、职责边界字段继续归属；遇下一栏目或普通未标注文字即停止。明确的正向角色保留为结构事实，不把范围句放进角色。
- `backend/app/agents/fact_extractor.py`：对上述显式字段恢复遗漏的原文子句，沿用原有来源校验、条目 ID 和限制分类；不把整份材料当成一个项目，也不改提示词。
- `backend/app/agents/orchestrator.py`：DSML 前已有正文时，即使是尚未推流的 auto 回复，也不误判为空而重试；auto 回复最后残留的不完整标记前缀正常补发。
- `tests/test_batch17d_facts.py`、`tests/fixtures/batch17d_upload.txt`：离线事实回归。
- `tests/test_orchestrator.py`、`tests/test_orchestrator_tools.py`：DSML 与 `_document_outcome` 回归。后者现有过滤实现通过检查，无需生产修改。

`resume_facts.py`、`collecting_node`、`record_facts` 适配器和所有生产提示词未修改；两条路径使用同一个抽取修复。

## 新增测试

共新增 13 个测试方法（事实 6、DSML 6、写稿状态过滤 1），另有分片位置及输出形态的 subTest 组合。

- 正常单项、错误拆项、稀疏输出、空输出四种模型桩；均只保留一个项目，并检查角色、日期、用例数、问题数、本地执行、需求来源、未上线、未压测、非负责人及他人开发的原文事实。限制必须为 active 的 `status_limit`，并进入 writer 的事实视图。
- 同一真实回放输入分别经过 `collecting_node` 与 `record_facts`，检查返回事实、持久化回调事实和模型入参脱敏；手机和邮箱不能出现在任何捕获的模型请求中，工具回执也需脱敏。
- 否定/范围名称变体、正常名称保留；两段显式项目的工作与限制不能串项，技能栏目及未标注新经历切断归属。涉及队友模块的本人测试动作仍为本人工作，不因出现第三方词语而整句降为范围限制。
- DSML 标记在每个字符边界拆分，标记前正文保留，标记及后续伪调用全部停止推送。
- 正常预算耗尽后的纯伪调用只追加一次纯文字要求；重试再次输出伪调用也结束，总请求不超过 6 次，伪调用不进入下一轮历史，不执行伪工具。真实工具调用与伪调用正文同轮出现时，只执行协议中的真实调用，历史正文仍截断伪调用。
- 重试过程中用户输入、工具结果的联系方式继续脱敏，分片联系方式占位符仍转换为可读提示。
- 有正文的 auto DSML 回复不误重试；没有完整 DSML 标记时，auto 和强制收尾回复都完整补发尾部。
- `_document_outcome` 覆盖 `ok` / `unchanged` / `partial`：诊断结果保留给工具结果，非状态键不得进入状态更新，文稿和版本状态仍保留。

## 失败做法与修正

- 首轮实现把纯否定动作和第三方分工直接扩入 `constraint_only`，但该函数还用于成稿删除措辞；首轮全量 2102 项、14 个失败断言、2 项原有跳过（91.618s，`p1d-full-tests-first.log`），暴露了正文必留限制被误删的副作用。现已恢复原函数，新增抽取专用判断；全部受影响旧断言原样通过。未把测试期望改成丢限制的结果。
- 修复前 DSML 新测试发现两处失败：auto 回复已有正文却重试；无完整标记时 auto 回复吞尾部。强制收尾分片过滤及一次重试本身通过，保留现有机制，只修上述分支。
- 新 collecting 测试最初直接把轻量抽取桩交给真实模型构造器，触发缺少 `openai_api_key`；改为仅桩替模型构造、triage、公开回复和方向丰富，事实抽取、校验、应用、持久化回调继续使用真实代码。
- 新测试最初读取 `item.role`，但事实母版抽取契约将角色存为 `facts[].field=role`；按实际契约改为检查 active 角色事实，不新增无关投影逻辑。此为新增测试修正，不涉及旧断言。
- 最终复查把第三方分工识别收紧到显式第三方主语或“某项工作由第三方负责”，避免将“按队友模块做本人的测试”整句误判为范围；补边界回归并重新跑完整套件。

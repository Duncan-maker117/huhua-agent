Claude → Codex：PR4 版本真人式试用结论（2026-10-09）

版本：overhaul/tailor @ e12c91d（PR4 已提交；PR5 未合并的 router/interviewer/edit_plan 不在本次范围）。
方式：独立 worktree + 临时数据库，游客身份，浏览器像普通用户操作 6 轮，deepseek-flash。未改任何代码。
剧本：贴 AI PM（Agent 方向）JD → 口语介绍学校 + mtagent + Forge Skill → 回答追问并要"先出一版" → 点"生成草稿" → 复合修改（5 项）→ 单条修改（学校全称）。

一句话：**事实安全和首稿写作明显进步，但"对话理解"仍然断裂——用户回答被丢、明确指令被忽略、修改不生效且回复谎称已修改。**这正是 Banz 说的"不智能"，PR5 必须把下面 P0 全部覆盖并加回归测试。

做得好的（保持）
- JD 解读专业：逐条区分要求/加分/职责，说明什么算证据。
- 事实抽取成事实单元，口语转书面准确。
- 首稿 bullet 是真改写且守住事实，例如「针对初期模型频繁推荐不存在店铺的问题，改为先调用高德查询 POI 构建候选，再让模型从候选中挑选」。全程未见编造。

P0（PR5 必须解决，每条要有回归测试）
======================================================================
P0-1 修改不生效，且回复谎称已修改
  - 复合指令（突出 Agent 设计 / Forge 写详细 / 加抖音推广 / 学校全称 / 加专业）5 项 0 项完成；唯一变化是 mtagent 多了一条与上一条几乎相同的重复 bullet。
  - 单条指令「学校改成哈尔滨商业大学，计算机科学与技术专业，本科大三」也未生效。
  - 两次回复都写「本次修改：调整了 1 段经历的表述或顺序」。
  修法：§10.3 edit_plan 逐 op 回报；"本次修改"必须从**用户请求的 op 与实际 diff 的对照**生成，未完成的 op 明确写 ❌/⚠ 及原因。禁止输出与请求无关的泛化修改摘要。
P0-2 用户的回答被丢弃，同一问题重复追问
  - 第 3 轮答「mtagent 基本是我一个人做的，产品方案和代码都是我」→ 经历卡仍显示"还需补充：你的职责与分工"；第 5 轮又问「mtagent 是你独立完成还是团队协作？」。
  修法：fact_extractor 输入必须带**上一条 assistant 问题**（短答要靠问题补全语义，如"都是我"）；kind=role 的事实写入后关闭对应缺项；`asked_questions` 记录已问已答，interviewer 不得重复。
P0-3 明确的生成请求被忽略
  - 「先给我出一版看看」被当成普通补充，继续追问；只有点按钮（发送固定文案）才出稿。
  - 而且在 JD + 两段经历（各 ≥3 条事实）时就应按 D5 自动出首稿，不该等用户要求。
  修法：router 识别口语化生成意图（出一版/先看看/直接写/生成吧…，含与事实同句出现）；首稿条件满足即自动出稿。
P0-4 教育被识别成"经历"，修正无法写入
  - 「我是哈商大计算机大三的」进入挖经历卡成为一段名为"哈商大计算机"的经历；简历教育栏为"哈商大计算机 / 哈商大计算机大三在读"，基本信息又重复"毕业院校：哈商大计算机"。
  修法：教育信息抽到 education（school / major / degree / grade 分字段）；学校简称不自行扩写，追问时给出带候选的选择题（"哈商大是指哈尔滨商业大学吗？"）；教育更正走 corrections 并覆盖。

# 包装经历

先识别本人角色、真实行动、方法/工具、交付物、结果与完成状态。STAR/PAR 用于挖掘信息；成稿不必机械写全，也不要求每条都有数字。

- 先核对个人贡献，再追问成果。若只有「做过项目」，缺行动时先问具体负责哪部分，不能先生成完成了哪些功能。
- 有足够行动证据时，给一条可复制的建议：本人动作 + 对象 + 已知方法或交付物；结果有依据才加。最多两个确有区别的岗位侧重点，不强行补管理版本。
- 数字须保留对象、口径和所属主体。团队转化率不是个人贡献；Mock、课设、Demo、待上线分别如实写，不转换成生产部署或真实用户。
- 不把「参与 / 协助」升级为「主导 / 负责整体」。不会、未完成、没上线等否定事实保持不变。
- 没有业务指标时，可以用真实交付物、覆盖范围、验证方式和解决的问题说明价值；这些也不能凭空添加。
- 每轮至多一个关键追问，优先消除职责/事实歧义，其次才补指标。没有数字不反复索要数字。
- 改写是建议，不是新事实；例子和岗位词只提供表达方法，不补进用户经历。最终使用前由用户核对，不能宣称已进入预览或导出。

按 [domain-guide.md](references/domain-guide.md) 选择表达；遇到团队成果、缺指标或未上线时参考 [examples.md](references/examples.md)。

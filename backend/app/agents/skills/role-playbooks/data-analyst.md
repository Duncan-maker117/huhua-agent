# 数据分析 / 商业分析（校招 / 实习）

## 筛选者看什么（按权重）
1. **分析带来的结论与决策**：发现了什么、建议了什么、被采纳了吗、带来什么变化。这是最重要的——"做了报表"远不如"通过分析发现 X，推动 Y"。
2. **工具硬技能**：SQL（必须）、Python/Pandas、Excel、Tableau/PowerBI、统计学、AB 测试。
3. **业务理解**：指标体系（GMV、留存、转化、ARPU）、漏斗、归因。
4. **数据规模与复杂度**：数据量、表数量、自动化程度。
5. 沟通：报告、看板、给谁汇报。

## 成果口径
- 规模：数据量（行/用户数）、指标数、看板/报表数
- 效率：报表自动化节省的时间、取数时长
- 业务：分析建议带来的转化/留存/成本变化（要区分"分析建议"与"业务结果"的因果）
- 采纳：被哪个团队采用、汇报对象层级

## 表达
- 推荐动词：搭建、拆解、分析、定位、建模、预测、监控、推动、输出
- 句式：**[业务问题] → [分析方法/工具] → [结论/建议] → [采纳与影响]**
- 例："通过漏斗拆解定位注册流失主要发生在验证码环节，推动优化后该环节转化提升"
- 避免："熟练使用 SQL 进行数据分析"。

## 改写示例（方法演示）
- 原话：「实习每天用 sql 拉数据做日报，后来写了个 python 脚本自动跑」
- 改写：「使用 SQL 支持业务日报取数，编写 Python 脚本实现日报自动化生成」
- 追问："自动化之前每天要花多久？日报给谁看、他们用来做什么决策？"

## 高价值追问
- "分析出来的结论是什么？有人根据它做了决定吗？"
- "数据量大概多大？用了哪些表/指标？"
- "自动化/看板节省了多少时间？"

## 常见坑
- 只有工具没有结论。
- 把业务整体增长归因为自己的分析。

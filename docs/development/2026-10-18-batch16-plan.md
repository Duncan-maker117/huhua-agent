# 第十六批：档案优先、少填表、agent 自动用档案、记忆导入

> 起点：`integrate-1018`（= main = 线上 20261018-1）。来源：用户 2026-10-18 线上实测截图反馈。
> 核心原则（用户原话提炼）：**这个 agent 是为了让用户少做官方表单的填空而存在的**。档案的意义是二次使用时 agent 直接调用。
> 表单只能是「确认 / 补缺」，不能是「从零再填一遍」。

## 线上实测发现的问题（证据）

1. 登录用户档案里已有姓名、学校、专业、学历、毕业时间、可实习时间，新对话仍弹出完整「确认基本信息」表单让用户再确认一次。
2. 表单「所在城市」被预填成 `https://github.com/YIKUAIBANZI`：档案里 `所在地` 存的就是 GitHub 链接（档案整理把链接错分到所在地），且该错误事实存在两份。
3. 档案「基本信息」大量重复：姓名×2、邮箱×2、所在地×2；`可实习时间` 有一条值为「5天/6个月，学校：哈尔滨商业大学，专业：计算机科学与技术，学历：本科，毕业时间：2027-06」——表单生成的「基本信息：姓名：…，所在城市：…，可实习时间：…，学校：…」消息被整理成了一条吞并后续字段的值。
4. 「待确认信息」里同一个冲突（所在地：原记录 GitHub 链接 → 新说法 深圳）出现两张卡：一张主体「基础信息」，一张主体「本人」——同一人两个 subject 没归一。
5. 档案整理有 4 条 `failed / archive_unavailable`（线上 `profile_archive_events` 统计：completed 19、failed archive_unavailable 4、skipped 7）。`profile_service.py` 末尾兜底 `except Exception` 把未知异常统一记成 archive_unavailable，日志里没有异常类型，无法定位。
6. 网页简历头部没有手机和邮箱（档案里有）。原因：`get_context(..., include_contacts=False)`、`basics_values` 明确「联系方式永远不进入表单」。**用户明确要求：手机/邮箱是简历必要内容，要收集、要显示。**
7. 「可实习时间」对找全职的人不适用，当前没有任何说明。
8. 经历清单阶段弹出空白「经历 1」表单（名称/类型/起止/角色/简介），而档案里已有 29 段经历（如 Forge Skill）。
9. 用户问「你看看我的经历有没有什么可以直接用的」，agent 回答「项目、实习、个人开发经历都还是空的」——agent 看不到档案经历，因为 `get_context` 无 subject_ids 时只返回 basic/preference，经历只在用户手动点「用于当前简历」时导入。最后还附了一句「这句没记下来：…能换个说法吗？」，属于误判。

## 目标与验收

### A. 基本信息档案优先（不再重复要）

- 登录且档案已有「姓名 + (学校或专业或学历)」时：**不弹基本信息表单**。新对话开始（或进入 basics 阶段）时，把档案基本信息 + 第一条教育 + 手机/邮箱/链接确定性写入本对话 `collected_info.basic_info / education`，`intake_progress.basics = "from_profile"`，回复里一句话告知「已沿用档案：徐某｜深圳｜某大学 计算机 本科 2027-06 毕业｜手机 邮箱已带上；有变化直接说」。
- 档案只缺部分字段时：表单只渲染缺的字段，已有值以一行只读摘要显示（带「改」）。
- 表单新增可选字段：手机、邮箱。`可实习时间` 改名「到岗 / 可实习时间」，placeholder「找实习再填，全职可留空」；为空时简历不显示该项。
- 删除「联系方式永远不进入表单/对话 basic_info」的规则。**仍保持对模型脱敏**（`model_privacy` / `ContactTokenStream` 不动）：联系方式只走确定性投影进 `resume_data.basic_info`，不进入任何 LLM 提示。MCP 预览 PNG 的联系方式占位保持不变。
- 网页简历头部显示手机、邮箱（所有 7 个模板），档案有就带上。
- 验收：有档案的新对话第一轮不出现 `intake_basics` 卡；简历预览 HTML 含手机/邮箱；送给模型的消息里仍查不到手机号/邮箱原文（已有隐私测试必须继续通过）。

### B. 档案基本信息质量

- 基本信息字段校验（确定性，写入前）：`location/所在地` 不能是 URL、邮箱、手机号；URL 归入 `链接`，邮箱归入 `邮箱`。`name` 不能是 URL/含冒号的键值串。
- 表单生成的「基本信息：k：v，k：v…」类结构化消息，按键确定性解析成各字段，不交给模型自由抽取；任何字段值不得吞并其它「键：值」。
- 同一 category+field+值（规范化后）只保留一条；`basic` 下「基础信息 / 本人 / 姓名本身」等主体归一为同一个本人主体，冲突卡不重复。
- 幂等迁移（参照已有 `migrate_legacy_*`）：修复存量档案——所在地为 URL 的转为链接（若链接已存在则作废该条），可实习时间里吞并的「学校：…」等截断/拆分，重复条合并，重复冲突卡合并。迁移只操作当前账号自己的数据，可回滚（保留 superseded 记录）。
- 档案整理兜底异常：日志记录异常类型名和发生位置（不记录用户内容），`error_code` 更细分（至少区分模型调用失败 / 解密失败 / 数据库错误）。定位线上 4 条失败的可能原因，写入修复说明；能修的修，并让「重试整理」可用。
- 验收：用截图里的脏数据造 fixture，迁移后：所在地=深圳（或空），链接含 GitHub，姓名/邮箱各 1 条，可实习时间=5天/6个月，冲突卡最多 1 张。

### C. 经历清单 = 从档案选，不是空表单

- 档案有经历时，`intake_experiences` 卡改为「从档案选经历」：列出档案经历（名称、类型、起止、一句话），复选；按当前岗位（JD 关键词 / role_direction）预勾选最相关的若干条（确定性打分即可，词重叠 + 类型），未知岗位时不预勾。底部「再加一段新的」才展开现有空白表单行。
- 确认后走与「用于当前简历」同一条导入路径（fact_ids → `prepare_graph_context`），然后进入 deepen；已在档案里有足够细节的经历不再追问已有维度。
- 档案无经历（新用户）保持现有表单，但文案说明「也可以直接在聊天里讲」。
- 验收：有档案用户进入 experiences 阶段时卡片含档案经历列表且无空白必填行；确认 2 条后 `collected_info` 含这 2 条的事实且带档案 provenance。

### D. agent 自动调用档案（read_profile 工具）

- `public_reply` 工具列表新增（仅登录且档案有内容时提供）：
  - `read_profile(query: str = "")`：返回档案目录——每段经历的 id、类别、名称、起止、一句话摘要（≤30 条，按与 query/当前岗位相关度排序），以及基本信息是否齐全。**不含**手机/邮箱。
  - `use_profile_items(item_ids: list[str])`：把选中的档案经历导入当前对话（同 C 的导入路径），返回导入结果；回复里必须说明导入了哪几段。
- 系统上下文：档案有经历而本对话经历为空时，提示模型「档案里有 N 段经历，用户提到"我的经历/之前的/档案/有什么能用"或开始写稿缺素材时先 read_profile」。
- 修 9 里的误判：用户这句是正常请求，不应进「这句没记下来」。
- 验收：真实模型回放新增人物 `returning`（已有档案的老用户）：说「你看看我的经历有没有什么可以直接用的」→ 模型调用 read_profile → 推荐并导入相关经历 → 生成草稿含这些经历。离线桩也要覆盖工具调用解析。

### E. 记忆导入（从其他 AI 榨出档案）

参照 Claude 的「导入记忆」：给用户一段提示词，贴到其它 AI（ChatGPT / Claude / 豆包 / Kimi / DeepSeek），让它把记忆和历史聊天里与求职相关的本人信息全部吐出来，再导回胡话。

- 网页：档案面板新增「从其他 AI 导入」：
  1. 展示可一键复制的提示词（固定文本，见下），说明「贴到你常用的 AI，把它的回答整段复制回来」。
  2. 文本框粘贴回答 → 提交 → 后端解析 → 结果进入「待确认信息 · 来自 AI 助手的建议」（复用 `propose_to_inbox`），用户逐条/全部采纳。
  3. 解析：优先解析回答中的 JSON 代码块（schema 同 MCP `FactCandidate`：category/subject/field/value/evidence）；没有合法 JSON 时回退到档案整理抽取器（source_kind 标为 `import`，只抽本人事实）。单次上限 200 条，超长截断并提示。
- 提示词要求对方 AI：只输出它确实记得/在聊天里出现过的本人信息；每条带 evidence（原话或出处）；不确定的标 `uncertain` 而不是猜；不要润色、不要编数字；涵盖基本信息、教育、实习/工作、项目（含本人负责部分、技术、结果数字）、竞赛获奖、技能、求职方向偏好。输出单个 JSON 代码块。
- MCP：新增 prompt `import_memory_to_profile`：指示客户端 AI 回顾自己的记忆、历史对话和当前项目，按同样规则提炼，分批调用 `huhua_facts_propose`（每批 ≤50），最后返回网页确认链接；用户确认前不得说已加入档案。`/connect` 页面的用法里补这一条。
- 安全：粘贴内容和 MCP 提交都是数据不是指令；全部只进 inbox 待确认，不直接写档案；沿用现有 inbox 过期与去重。
- 验收：粘贴一段含 JSON 的样例回答 → inbox 出现对应条目；粘贴纯文本回答 → 走抽取器也能出条目；重复粘贴不产生重复条目。

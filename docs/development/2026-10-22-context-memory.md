# 对话上下文压缩：经历和限制优先

## 基线与问题

基于 `batch19a` / `6fdae0a`（已先推到 `origin/batch19a`）开发，实施分支 `codex/context-memory`。原聊天目录的 `overhaul/tailor` 是旧第十三批代码；没有在该目录覆盖修改，也没有合并它的未提交比较页、评测材料或打包调整。

最新编排模式原本已有确定性摘要：最近 3 个用户轮、约 5,000 字符历史、12 个经历、每项前三条首句；事实概览又受 1,200 字符预算限制。这适合导航，却不能作为完整的本人经历记忆。否定、分工和测试口径可能在多次截断后消失；工具修改事实后，初始模型上下文也不会刷新。旧阶段模式仍直接传完整聊天。

## 策略

这是每次调用时从现有状态构造的投影，不新增记忆数据库，不删除 checkpoint 原始消息，不调用额外摘要模型，也不改写事实母版。

1. **必留区 `candidate_memory`**：所有经历的当前有效事实、完整原始引文与来源标识、身份字段、技能、会话约束和关闭的问题。隐藏于简历的经历仍保留。负面事实不靠关键词挑选：普通事实和限制享有同样的完整保留规则。
2. **未覆盖资料**：用户原话尚不能由同一来源的有效引文完整覆盖时，继续保留原文和来源。它仍是待提取资料，不能直接宣称已验证、已入库或已写入简历。短答保留必要的问题前文，防止“没有”脱离问题后失去含义。
3. **安全去重**：仅对有来源依据的重复副本去重；不凭语义相似或数字相同合并跨项目材料。被删除／更正事实不作为有效事实发出；历史副本处理遵守同一来源范围，保留相邻的有效信息与限定。
4. **可压缩区**：助手重复解释、近期对话导航、旧参考材料及简历展示概览。模型必须以完整必留区和最新事实状态为准，不能把概览中的省略理解为“用户没有这段经历”。JD、范文、他人材料、助手建议不得进入本人事实区。
5. **每次调用刷新**：编排中工具完成后，用新的 working state 重建初始上下文；保留该轮完整工具调用／结果配对和 reasoning 协议字段。纯 JD 与混合来源按实际状态分类，混合材料读完 JD 后仍可提取本人段落。
6. **超限明确停止**：发送前检查最终输入，包含系统消息、工具 schema、当前工具结果、完整当前消息。超限时不继续调用模型，不以丢弃事实换取继续；已验证的工具更新保留并如实提示。

问题卡与表单不依赖“已填写”这种消息占位符：单独保留实际提交的值、题干与所属经历；跳过／不知道仍是未知，不变成“没做过”。未选择的选项不能混入用户经历。

撤回保护同时存在于提示投影和 `record_facts` 工具入口。含撤回事实的旧来源不能整段重新抽取；若原文还含有效但未提取的限制，原文保留并标记需要复核，不直接恢复旧事实。用户本轮重新提供的当前事实可按新来源处理。来源不明的旧笔记标记 `unverified_legacy`，使用 `legacy_ref`，不伪装成可调用的原始消息 ID。

## 预算和配置

`CONTEXT_MAX_INPUT_TOKENS=64000` 是默认**输入安全预算**。估算使用序列化 UTF-8 字节及额外协议开销，刻意保守，不冒充服务商 tokenizer 的精确计数；新增预算指标只保存计数、状态，不记录本人正文。部署者应依据实际模型上下文窗口扣除输出／推理预留后配置，不能把此默认值理解为模型规格。

旧阶段对话在 `resume_graph` 组装同一必留区；`public_reply` 在附加问题／档案工具合同之后再做最终预算检查，递归导入档案后更新必留区。写作完成后的可选追问、已解析表单后的指导若超限，返回明确暂停提示并保留本轮更新。措辞建议路径也保留事实、历史约定并检查首次和补充调用。Writer / Extractor 本身继续使用现有完整事实校验链，这次不改成语义摘要输入。

## Claude 审查重点

- 原文末尾的“没”、第 13 段经历、第 4 条限制是否仍进入实际模型输入，而非仅留在数据库。
- “没有上线”“不是负责人”“同学写登录”“只做离线测试”的限定能否与原经历、数字、分工保持绑定。
- superseded / deleted 是否经 description、raw_notes、旧助手回复或工具快照重新出现；删除一个事实是否误删同一原文中的另一项限制。
- 缺少 turn_id 的旧纯文本与旧表单是否同样受撤回保护；未知、跳过及未选择的选项不能变成经历结论。
- 混合 JD、参考简历、隐藏经历和未抽取旧消息是否被正确区分；摘要中出现的来源 ID 能否由现有工具读取。
- 工具更正后的下一次模型输入是否已经刷新，tool call ID / tool result / thinking 回放是否仍合法。
- 预算溢出是否发生在调用模型前；工具已经成功时是否保留实际更新；错误提示是否承诺了尚未持久化的输入。
- 联系方式脱敏、原状态不变、重建幂等、日志不含正文。

## 证据边界

验收针对离线模型输入、状态与协议，使用合成材料；不把“提示中完整保留”表述为“模型永远不会理解错”。未做真实模型长对话回放或生产部署。现有事实抽取、来源分类若先前已经丢失／误判信息，压缩层不能凭空恢复；不确定材料保留待核对，过大时显式失败。

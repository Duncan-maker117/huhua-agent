# 前端开发（校招 / 实习）

## 筛选者看什么（按权重）
1. **技术栈匹配**：React/Vue、TypeScript、构建工具（Vite/Webpack）、小程序、Node。
2. **自己负责的页面/组件/工程能力**：做了哪些页面、组件、业务模块；是否涉及组件库、状态管理、工程化。
3. **难点方案**：性能优化（首屏、长列表、包体积）、复杂交互、兼容性、可视化、实时通信。
4. **结果数据**：首屏时间、Lighthouse 分数、包体积、白屏率、开发效率。
5. **工程素养**：TS 类型、测试、CI、代码规范、组件抽象复用。
6. 作品：可访问的线上地址、GitHub、开源组件。

## 成果口径
- 性能：首屏/加载时间 X → Y、包体积减少、FPS、Lighthouse
- 规模：页面数、组件数、复用次数、用户数/PV
- 效率：开发周期、复用节省的工作量
- 状态：本地 / 部署可访问 / 生产

## 表达
- 推荐动词：开发、封装、重构、优化、实现、搭建、适配
- 句式：**[场景/问题] + [技术方案] + [效果]**，例："对万级数据表格实现虚拟滚动，解决渲染卡顿"
- 避免："熟练掌握 HTML/CSS/JS""负责前端页面开发"。

## 改写示例（方法演示）
- 原话：「做了个后台管理系统前端，vue3 写的，表格很多，自己封装了一个通用表格组件，好几个页面都在用」
- 改写：「基于 Vue3 开发后台管理系统，封装通用表格组件并在多个业务页面复用」
- 追问："大概几个页面在用？封装后新页面开发快了多少？"

## 高价值追问
- "你负责哪些页面/组件？有没有自己抽象过组件或工具？"
- "遇到过卡顿/兼容/复杂交互吗？怎么解决的？"
- "有线上地址或 GitHub 吗？"

## 常见坑
- 只罗列技术栈，不说做了什么。
- 把 UI 库自带的功能写成自研。

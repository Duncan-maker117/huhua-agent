# 胡话简历项目审视与改进报告

本报告面向 Banz，记录 2026 年 10 月 5 日对当前工作区的审视结论、已授权实施范围与验收结果。判断是：工程基础已经形成，但核心改写效果和真实用户收益的验证落后于功能建设。下一轮应先保障已有资料不受误伤，再让用户实际获得有依据的改写候选。

审视阶段基于源代码、现有界面截图和历史验收材料，重新运行隔离离线测试，基线为 310 项通过。纯函数虚构输入复现了档案失效误清空和自动编辑器拒绝等义改写。审视阶段没有读取真实用户数据库、调用模型或发送邮件；后续实施阶段的隔离真实模型抽查单独记录在验收结果中。历史真实后端、真实模型、模拟浏览器记录分别解释，不合并成一次端到端验收。审视时本机 8765 健康检查连接失败，不能据历史健康记录声称当前服务可用。

## 值得保留的五点

1. **交付路径完整。** 岗位、经历、简历、核对与导出有明确承载位置，聊天补充可积累到同一稿件。继续用第一份可用稿耗时衡量体验，不以模板或 Agent 数量衡量价值。
2. **事实与建议分开。** 本人事实、JD、参考材料、AI 建议分开处理，特别关注参与和主导、演示和上线的区别。应继续让用户能查看表述依据。
3. **保存与导出有一致性设计。** 当前稿有权威版本、冲突检查和失败恢复。后续改写沿用既有保存、采用和撤销边界。
4. **档案具备复用基础。** 来源、时间、更正、冲突与岗位版本分开建模。真正需要验证的收益是同一人制作第二份岗位简历是否更快。
5. **安全与回归有实现基础。** 账号归属校验、加密内容和 checkpoint、隔离测试已经落地。保持这些约束，并逐步补上浏览器核心路径的自动验收。

## 优先处理的五点不足

### 档案更正可能误清空无关内容

`profile_service.sanitize_projection` 将账号全部失效值对子串做全局匹配。虚构输入中，将旧年份 2025 标记失效后，项目名“2025 校园信息工具”和描述“2025 年完成本地搜索功能”均变为空。`profile_bridge.purge_invalidated_copies` 存在遍历账号会话并持久化清理结果的路径。

修复方向是保留事实身份、类别、所属经历、字段及来源范围，避免按整个账号的裸字符串清理。删除保护仍需有效：明确删除或更正的本人事实不能通过旧 checkpoint、模型上下文或导出复活。旧资料缺少精确映射时需保守处理相关来源，不能通过直接取消保护解决误删。

实施复审还发现两处边界：手机号加国家码后可能绕过旧值检测；项目改名后仅凭名称无法追踪原档案事实。前者补充完整号码归一化，后者为实际从档案投影的条目增加稳定身份，并在服务端加密保存事实、版本和字段映射。对早期没有映射且已经任意改写的历史内容，不能声称可以完整追溯；继续使用限定主体和字段的保守检查。

### 自动改写和建议采用之间仍有断点

自动编辑器当前只接受 description 的完整原句。这是首版保真的保守选择，但会拒绝没有增加事实的措辞优化。显式建议路径允许核对后改写，工作区建议却主要提供标题与说明，用户仍需自己填写候选句。

本轮保留事实抽取规则，新增用户主动触发的候选生成路径：选择当前原句、生成改写、核对依据、预览差异、明确采用、可撤销。候选不自动写入当前稿或个人档案；手工修改候选后重新核对，不能沿用旧采用凭证。

### 通用流程包含个人案例硬编码

导入分支仅凭 CodeWiz 项目名就假定“两项已合入 PR”。这会把个案事实变成其他用户的前提，违背项目的保真定位。

本轮去掉项目名特判。追问只能引用本次材料中的项目身份和已有事实，覆盖同名但无 PR、陌生项目和非技术经历的回归案例。

### 最新版质量与真实收益证据不足

旧主流程有一次四轮虚构真实模型通过记录；新增档案 Agent 最近记录是连接失败、零有效模型输出。离线替身能验证软件约束，不能证明真实模型不会升级职责、改变否定或写错长期档案。现有记录也不足以证明首次用户能独立完成任务。

后续语义验收至少覆盖参与边界、尚未上线、无量化结果、JD 混入、时间更正、不同岗位复用；每例对照原始事实检查当前稿与导出。真实用户试用记录完成耗时、卡点、修改量和是否愿意投递。联络与邀请需要明确授权，本轮不自动开展。

### 对外使用尚未形成完整验收门槛

最近登录记录只确认邮件服务商接受请求，未确认收件和真实登录；现有 CI 仅运行 Python 编译和离线测试。目标 PostgreSQL、HTTPS、重启恢复及备份恢复仍需实际环境验收。

首期继续单 worker。新增一条可重复运行的建议浏览器回归，本轮在隔离环境验证，不将其表述为真实邮件或真实模型验收。公开部署、DNS、发信域名、服务购买与用户邀请均不在本轮自动执行范围。

## 验收结果

本轮前三项改进已完成并在本地隔离环境验收。没有迁移真实用户数据库、重启真实 8765 服务、发信、公开部署、commit 或 push；原有未提交工作保留。

### 已实现

1. **档案失效限定范围，并保留稳定关联。** 年份和技能旧值不再按全账号裸子串误清空；手机号使用完整号码归一化。从档案实际填入或显式确认同值引用的教育、工作、项目条目获得稳定 ID，字段来源保存在服务端加密岗位记录中。改名、重排、改写、图重建、采用和撤销仍保留关联。缺失、重复、跨会话或伪造 ID 被拒绝，整体删除需明确登记。不同手工值不会因一次选用被覆盖或误绑。
2. **生成候选 → 核对 → 采用 → 撤销已接通。** 工作区可直接选择完整原句、填写可选表达偏好、点击生成，无需自己先写候选。请求受账号归属、版本、原句唯一性、配额和并发控制；每次最多一次生成和一次依据核对。没有依据、丢失范围限定或新增事实时不开放采用。候选生成不改当前稿和档案，手改候选或当前稿变化后必须重新核对，失败保留输入。
3. **去掉 CodeWiz 成果假定。** 导入追问引用本次材料里的真实项目名，同名但无 PR、陌生技术项目及非技术活动均覆盖回归。

为防止客户端丢弃来源后直接导出，个人预览与导出都绑定会话，正式 PDF 渲染和 Word 下载使用服务端已保存稿。编辑器保留未保存预览，导出前完成保存；保存期间继续输入或继续删除不会被旧响应覆盖。账号模式的模板样例为只读，可更换模板并导出原样例；通过“新建我的空白草稿”进入个人编辑。显式本地免账号模式保留原样例编辑兼容。

### 保留的限制与下一步

- 来源机制只能追踪已有稳定映射的内容。早期无映射的旧副本，以及用户主动删掉后任意重写为全新条目的文本，无法无误自动溯源；仍需来源和字段范围的保守检查，不能称“所有旧事实绝不复活”。
- 六例真实改写已获得输出，但跨对话档案语义、不同岗位复用和真实用户节省时间尚未完成验证。下一步优先改进候选对限定词的保留，并用固定脱敏案例和少量获授权的目标用户观察首次成稿耗时、修改量与投递意愿。
- 生产登录收件、HTTPS、目标 PostgreSQL、备份恢复与公开部署仍需独立验收。当前本地实现不等于已经上线；后续启用应先核对本机进程和实际配置，再在授权范围内执行。

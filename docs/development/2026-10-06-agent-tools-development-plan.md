## 用户如何使用

### 读取明确的招聘链接

用户在输入框粘贴一个完整招聘链接，或者点击“读招聘链接”。系统显示读取状态，取得网页正文后解码岗位要求，在右侧“读岗位”展示原链接、关键条件及可核对的原文。

正文里的要求只属于招聘方。例如，网页要求熟悉 Kubernetes，而用户只讲过 Flask 课程项目，Agent 应指出缺少 Kubernetes 的个人证据，不能在用户技能栏自动补上 Kubernetes。

如果网页需要登录、只能通过脚本加载，或者禁止读取，界面保留链接，并提供粘贴原文和上传截图的回退方式。失败时不声称已经读懂岗位。

当前只对“单个完整链接且没有附件”的输入自动读取。这是前端固定规则，不是模型自主选择工具。链接与个人经历混在一起时，沿用普通聊天，避免把整段经历错误归类为 JD；后续是否支持混合输入，属于另一个待设计能力。

当前读取成功会把该网页作为目标 JD，即使会话中已经有其他岗位。如果 Banz 希望先比较再选择，则需要增加“读取预览 → 采用为目标岗位”的步骤；这是本次评审的可选改动，现有版本尚不提供该步骤。

### 按需查询公司和岗位

用户打开“查公司岗位”，填写公司名和岗位名，至少填一项。发给搜索服务的是这两个字段；原输入草稿、附件和整份简历不作为搜索词发送。

Agent 的输出应包含三类信息：公开来源实际说了什么；当前经历有哪些可对应的证据或缺口；接下来可以如何修改表达或补充事实。每项来自网页的判断标注来源编号，推断要与来源原话分开。

例如，来源强调接口测试，用户材料只说明自己参与了需求整理。合格建议是“保留需求整理的实际贡献；如果还做过测试，请补充具体动作”，不能直接生成“独立完成接口自动化测试”。

### 游客先体验再登录

游客可以聊天、上传材料、读招聘链接、预览模板和修改当前简历。搜索启用后也可在游客额度内体验。本次会话里的上下文仍用于连续交流；跨会话长期记忆、历史保留与正式导出要求登录。

登录应接续当前会话，保留输入和当前稿。网页材料随会话保存为引用资料，不能在登录认领时变成用户的个人事实。

## 工具和 Agent 如何配合

现有主流程使用 LangGraph 管理 JD、经历收集、成稿和检查。建议保留这个流程，把外部工具作为有边界的资料入口。

| 工具 | 输入 | 返回 | 后续处理 |
| --- | --- | --- | --- |
| `read_job_url` | 一个公开 HTTP 或 HTTPS 链接 | 标题、正文、最终链接、获取时间，及能提取到的发布日期 | 进入 `decode_jd`，更新目标岗位材料 |
| `search_job_context` | 公司名、岗位名，各最多 80 字 | 最多 4 条带来源的搜索摘要 | 进入 `research_job`，对照当前资料进行只读分析 |

读取链路为：明确输入 → 校验会话和额度 → 读取网页 → 标记为 JD → 解码 → 展示来源与岗位要求。

搜索链路为：独立关键词 → 校验会话和额度 → 查询公开资料 → 标记为参考 → 与当前经历对照 → 展示建议与来源。

搜索节点不更改简历阶段、目标 JD 或简历正文。把建议写进简历时，继续走现有“核对依据 → 用户采用”的路径；即使用户选择采用，新增个人事实仍需要其本人提供依据。

### 是否让模型自行调用工具

| 方案 | 能力与代价 | 本次建议 |
| --- | --- | --- |
| 明确入口触发 | 点击按钮或粘贴链接，每轮调用一次；行为可预期 | 保留为首期方案 |
| 有限的意图判断 | 模型从“无需工具、读链接、查岗位”中选择；服务端仍限制参数和次数 | 如果 Banz 希望对话更自然，再单独加入范围 |
| 自主浏览循环 | 模型继续拆问题、搜索、打开多个网页，需要调用预算、停止条件、去重及更多来源管理 | 暂缓，首期收益尚未证明 |

如果选择有限意图判断，用户明确说“帮我查”才进入研究意图；仅提到公司名不触发搜索。公司有歧义或搜索词混有个人信息时先澄清。工具结果仍受同样的事实边界约束，模型不能绕过服务端执行限制。

## 信息分别存在哪里

| 信息 | 用途与保存方式 | 能否进入本人档案 |
| --- | --- | --- |
| 用户明确提供的经历 | 当前简历的事实依据；登录后沿用既有归档规则 | 可以，需保留来源、处理冲突 |
| 招聘网页正文 | 岗位要求；来源类型为 `jd` | 不能 |
| 公司与岗位搜索摘要 | 公开背景；来源类型为 `reference` | 不能 |
| Agent 的改写和分析 | 候选表达与建议 | 不能直接当事实归档 |

来源随会话进入现有加密 checkpoint，即会话状态存储。游客遵守临时保留策略，账号会话遵守既有历史保留规则。首期不建跨用户共享的简历或网页资料库。

每条来源至少保留标题、链接、类型、内容和获取时间。发布日期只在来源明确提供时显示，不能用今天的读取时间代替。现有界面展示最近一组来源，编号对应最近一次研究回复；更早回复的来源回溯体验需要在多轮测试中重点检查。

搜索供应商只收到用户在独立字段填写的关键词。用于分析的当前经历和公开资料会发给既有生成模型；这一点应与“不把简历发给搜索服务”区分。文本联系方式沿用已有脱敏处理，研究分析不需要头像。

## 调用限制与失败处理

现有实现每轮至多一次搜索或链接读取。网页工具并发上限为 2，服务内总超时 15 秒，API 有 20 秒兜底；链接最多跳转 3 次，原始与解压后的内容分别限制在 1 MiB 内。链接正文最多取 12,000 字符，搜索摘要每条最多取 1,800 字符。

这些是当前技术边界，不代表整体分析在 15 秒内完成：网页工具之后的模型解码另受模型超时控制。较长正文可能被截取，界面与回复应避免暗示已完整审阅原页。

| 情况 | 用户看到的结果 | 处理原则 |
| --- | --- | --- |
| 缺少搜索凭证 | 搜索未开通；链接读取仍可用 | 不伪造结果，不自动换服务商 |
| 登录或动态页面无法读取 | 保留链接，提示粘贴原文或上传截图 | 不使用用户的招聘网站 Cookie 绕过限制 |
| 搜索没有可用结果 | 说明本次未找到依据，允许修改关键词 | 不拿旧结果冒充新结果 |
| 找到公开资料但模型分析失败 | 保留本轮来源，说明分析未完成 | 不把失败写成完整成功 |
| 网页信息互相冲突或岗位过期 | 展示冲突与时间，提示核对原页面 | 不自行合并不同公司的岗位要求 |
| 次数用完或供应商限流 | 说明稍后重试，保留当前草稿 | 无自动反复请求 |

目前沿用游客每日 20 次、账号每日 80 次的共享操作额度，以及 IP 和全站频率限制。额度在工具执行前预留，因此抓取失败、拒绝私网地址或工具并发已满，也会消耗本轮次数；缺少搜索凭证会提前拒绝，不消耗本轮。若改为部分失败不扣体验次数，仍需保留独立的请求频率限制，避免失败请求无成本地反复占用服务。

一次工具操作可能接着触发模型处理，不能等同于一次模型请求或固定金额。配置搜索服务时需要同时确认服务商的用量与费用上限，不能把应用限流称为费用封顶。

公开链接只允许连接公共地址，跳转后重新检查目的地，固定已验证的连接 IP 并保留 TLS 证书校验。网页文字中的指令只作为待分析内容，不能要求 Agent 导出私人资料、修改事实或改变工具权限。

## 怎样判断这一轮做好了

| 场景 | 应达到的结果 | 当前证据 |
| --- | --- | --- |
| 游客贴一份可访问的 JD 链接 | 读到正文并展示岗位、来源；不会要求先登录 | 已有一份真实公开页面验证，需补常见中文站点 |
| 常见中文网页编码或异常标签 | 正常提取；无法可靠识别则说明失败 | 已有离线回归 |
| 请求本机、内网或云元数据地址 | 在对外连接前拒绝，不泄露系统信息 | 已有边界回归和公网检查 |
| “公司＋岗位”真实搜索 | 结果对应目标，链接可核对；相近职位不冒充目标岗位 | 待凭证配置后验收 |
| 搜索仅找到摘要 | 明确材料范围，不说已读完整官网 | 有替身测试，待真实结果验收 |
| 来源写“精通某技术”，用户未提供该经历 | 不改个人技能或事实，建议保留待核对项 | 有隔离测试，待真实模型案例抽查 |
| 虚构网页夹带改变角色或虚构成果的指令 | 不执行网页指令，事实与来源仍可逐项核对 | 隔离测试覆盖资料分离，需补真实模型受控案例 |
| 同一会话多次研究或切换岗位 | 本轮编号正确，当前 JD 不被背景搜索覆盖 | 有状态测试，来源历史体验需人工检查 |
| 工具失败或用户中断 | 草稿保留，来源能查看，重新发送不会悄悄改变本人资料 | 已有本地替身验收，线上继续抽查 |
| 游客登录认领及另一账号访问 | 当前会话继续，引用资料不变为本人事实，其他账号读不到 | 已有加密后端回归；生产真实登录接续仍待验收 |

朋友试用时重点观察：能否顺利读入目标岗位；来源是否让人更容易核对建议；是否出现编造本人技能或贡献；失败后能否继续完成简历。记录具体案例和修改量，再决定是否投入更多自动调用能力。少量试用反馈不直接当作普遍效果结论。

## 后续候选能力

排版检查可以处理页数、溢出和可读性；作品集读取可以协助提炼项目材料；有限的自动工具选择可以减少点按钮。这三项暂不进入本次交付范围。优先级由首轮试用出现的实际问题决定，外部作品也不能仅凭一个链接就认定属于用户本人。
